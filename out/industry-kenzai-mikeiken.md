建材・住宅設備メーカーに未経験から入ることを考えるときは、業界の経験と、営業や開発等の職務経験を分けます。住宅や公共施設に関わった公務の経験にも、相手の要望の整理や関係者との連絡など、説明できる仕事があります。そのことと、今回の求人で必要な専門実務を満たすかは別に確認できます。

本記事は2026年11月時点の公開情報にもとづきます。確認日は2026年11月25日です。採用側の非公開の評価や採否は確認できません。以下は公式の仕事内容と本人の事実を照合する方法であり、公務員経験があれば採用されるという説明ではありません。

## メーカーの職務と販売、施工を分けて読む

今回確認したLIXILの公式求人は、ビル用建材の法人ルート営業です。建設会社、工務店、流通店などへの提案や販売が示されています。住宅や建築に関わる会社でも、今回の担当は法人への営業であり、自治体の発注手続きや施工の監督と同じではありません。

TOTOの公式求人では、水まわりのIoTシステムを開発するエンジニアの仕事が示されています。要件定義、設計、開発、発売後の対応、クラウドの企画や保守等を担う専門職です。住宅設備に関わる仕事という点は共通しても、LIXILの営業と必要な実務は異なります。

メーカー本体の採用、販売会社の営業、ショールームの案内、施工会社の工事、保守等は、雇用する主体と担当を確認して分けます。商品を見た経験や公務で購入した経験から、その商品の設計、販売、施工まで担当したとはしません。同じブランドの商品を扱っていても、雇用条件を別の会社へ移すことはできません。

| 確認する区分 | 求人で読む対象 | 公務の経験との線引き |
| --- | --- | --- |
| 法人営業 | 顧客、提案、販売、担当製品 | 発注側の照会や通知を販売にしない |
| 開発 | 本人が行う設計や実装、運用 | 委託先への連絡を自分の実装にしない |
| 商品案内 | 今回の募集に書かれた案内の範囲 | 別の営業や施工の条件を移さない |
| 施工・保守 | 技術や資格、現場の担当範囲 | 所管や検査を全ての施工実務にしない |

業界名から職務へ絞りたい方は、[掲載中の求人を仕事内容から確認できます](../?gov=1)。メーカー、販売、技術等の違いを読むために使えます。

## 営業は業界不問の範囲と必須経験を照合する

LIXILの前記法人ルート営業は、営業経験が二年以上あることと、普通自動車第一種免許を必須要件にしています。有形か無形か、既存か新規かといった営業の種類は問わないとされています。建設や建築資材の業界での営業経験は歓迎の欄です。

つまり、建材の業界経験が歓迎であることと、営業そのものが未経験でもよいことは同じではありません。公務で学校や企業と連絡した経験だけで、営業経験の要件を満たすとは判断しません。職歴の中に実際の営業があるなら、その対象、担当、期間を照合します。

行政の窓口で制度を説明したこと、調達に関する問い合わせをしたこと、事業者の要望を整理したことは、本人の経験として書けます。しかし、顧客への提案や販売、受注を担当していないなら、それらを実績として加えないようにします。接点のある工程と、経験していない販売の仕事を並べます。

免許についても、今回の記載と本人が保有する種類を確認します。別の求人にある条件を借りず、必要な条件の意味が不明なら採用担当へ照会します。関心や学習の予定は、現在保有する資格や経験の事実とは別の項目として扱えます。

:::insight
「業界の経験は歓迎」という求人を読むときは、その上にある必須条件を先に残します。建材を扱ったことがなくても、営業の実務が必要な募集はあります。公務で企業と連絡した経験を、名称だけで法人営業へ置き換える必要はありません。要望を聞いた工程、情報を確認した工程、他部署へ伝えた工程を具体的に書き、販売や受注を担当したかは別に示します。業界への関心と本人の職歴を分けると、応募条件に不明な点を絞れます。これは公務の経験を小さく扱うためではなく、今回の専門実務と照合するための整理です。必須経験が合わなければ、別の職務を比較する選択も残せます。
:::

## 開発は業種不問でも本人の技術実務が必要

TOTOのIoTシステム開発エンジニアは、システム開発の経験について業種を問わないとしています。ただし、要件定義、設計、開発、テスト、保守運用等の工程を一通り本人の手で経験していることを求めています。プログラミング言語による実装の経験も必須です。

同求人は、PMやPLとしてのマネジメント経験を必須としない一方、技術の実務を重視すると説明しています。管理経験がなくてもよいという記載を、開発の実務も不要という意味には読みません。調整や予算管理だけの経験で、実装の条件まで充足したとはしません。

公務で情報システムの担当をしていた場合も、本人と委託先の担当を区別します。自分で仕様を検討した範囲、自分でプログラムを実装した範囲、委託先が設計や試験をした範囲を整理します。部署として導入したシステムの全工程が、そのまま本人の技術経験になるわけではありません。

学習で作ったものを説明する場合も、実務で利用した開発や運用とは分けます。資格や学習を進めたことは事実として示せますが、それだけで今回求められる実務に代わるとは判断しません。内部のソースコードや設定、利用者のデータを応募用に持ち出す必要もありません。

## 架空例で発注者の経験と未経験を区別する

次の表は書き方のために独立して作成した架空例です。実在の応募者や企業回答、面談の記録ではありません。特定の求人の必須条件を満たす例でもありません。利用する場合は本人の事実へ置き換え、実施していない内容は削除してください。

| 項目 | 架空の記入例 |
| --- | --- |
| 関心 | 施設で使う設備に関心があり、メーカーの営業と開発を分けて調べている |
| 公務での担当 | 施設の利用担当から設備に関する要望を受け、内容を整理して技術担当へ伝えた |
| 本人の成果物 | 要望の対象、利用する場面、確認先をまとめた連絡用の一覧を作った |
| 他者の担当 | 技術上の判断は技術担当、製品の提案と工事は契約先が担当した |
| 経験していない仕事 | 商品の販売、受注、設備の設計施工、プログラムの実装 |
| 応募条件の照合 | 営業や開発の必須経験に自分の担当を自動換算せず、別の募集も比較する |
| 勤務の希望 | 通勤できる範囲を希望しているが、企業から勤務地の回答は受けていない |

この例なら、要望の整理と技術担当への連絡が本人の仕事です。「設備の開発を担当した」と書くと、実際にしていない設計や実装まで含むように読めます。担当した工程をそのまま示した方が、求人の専門実務との違いを確かめられます。

また、設備を導入した結果について確認していない効果を作りません。利用者の満足度や削減の成果を測っていないなら、その数字や心理的な変化は記述しません。本人が作った一覧、確認した相手、引き渡した内容等の事実から説明できます。

職歴の範囲を整理したい方は、[経験と希望する職務の照合を相談できます](../apply.html)。ご利用は無料です（紹介手数料は採用企業の負担）。経験や希望等により、求人の紹介や面談等をご提供できない場合があります。

## 勤務地や契約は記載の違いも残して確認する

LIXILの前記求人は、正社員で契約期間の定めがなく、試用期間を六か月としています。ただし、試用中の条件が全て同じだと本文から補いません。基本給や各種手当等も、本人に適用される条件を正式な提示で確かめます。給与のモデルや別の職種の条件を本人へ割り当てません。

同求人では、表題が熊本を示す一方、勤務地の欄に福岡市の住所が掲載されています。どちらが実際の勤務地かを推測で決めることはできません。応募を検討する場合は、この記載の違いをそのまま採用担当へ確認し、本人に届いた回答を記録します。

TOTOの前記開発職は、総合職の正社員で、将来的に国内外の異動や転勤の可能性を示しています。リモート勤務も部門のルールに従い、試用期間は対象外とされています。リモート可能という記載から、常時自宅で勤務できる仕事とは読みません。

仕事への関心と、本人が対応できる勤務の条件は別々に考えます。製品開発に関心があっても、勤務地や異動の範囲が合うとは限りません。希望する条件があるなら、それを希望として整理し、採用側が認めた内容と混ぜないようにします。

募集の受付や記載は変わる可能性があるため、閲覧時に公式ページを確かめます。終了した募集は過去の条件の参考として扱います。応募を送ったこと、受領の表示、選考の連絡、個別の条件提示はそれぞれ別の段階として記録できます。

:::insight
公務で施設や住宅に関わった経験は、扱った対象と担当した工程を残して比較できます。メーカーの仕事を調べるときも、製品を使った側、発注した側、設計や実装を行った側を区別します。未経験の分野に関心があることと、必須の営業や開発を既に経験したことは別です。本人の実務が整理できたら、仕事内容だけでなく、勤務地、異動、契約や勤務の時間も並べます。記載が食い違う場所は、都合のよい方を採用せず未確認として残せます。条件がまだ合わなければ、現職を続けて情報を集める判断も同等です。学習や応募を急ぐ前に、何を確かめる必要があるかを整理できます。
:::

## 未経験の範囲に合った次の行動を選ぶ

条件を読むためのメモには、必須、歓迎、本人が経験したこと、未確認の四つの欄を作れます。たとえば営業の必須条件には、本人が実際に販売を担当した期間を記入します。経験がなければ未経験と残し、関係者と連絡した期間を営業の期間へ加えません。開発でも、自分で実装した対象と、委託先の作業を確認した対象を別に記入できます。

過去に別の職業で営業や開発をしていた場合は、公務の期間と分けて照合します。公務員という現在の職名だけで経験を一括りにせず、本人の職歴全体から事実を確認できます。ただし、期間が合計できるかや対象経験に該当するかは、求人の記載と採用側の確認に従います。自分で条件を広げて解釈しないことが大切です。

候補の募集を見送ることも、業界全体を諦めることとは別です。今回の必須経験と合わない理由を記録すれば、別の職務を読む際に同じ条件を混同せずに済みます。

業界の知識が不足しているのか、職務の実務が不足しているのか、資格や勤務条件が合わないのかを分けます。それぞれ確認する相手や情報が変わります。求人で必須とされる経験を、商品に詳しくなることだけで代替できるとは限りません。

学習に取り組むなら、どの仕事を理解するためかを先に決めます。公開の商品情報を読み、製品の用途を整理することはできます。ただし、製品を知っていることと、安全や性能を判断できる技術の権限を持つことは別です。応募のために専門判断を代行する必要はありません。

公務の実績を説明する際は、住民や事業者の連絡先、内部の設計図、調達予定、非公開の価格や評価資料を持ち出しません。応募資料のために内部情報を私用の端末や外部の生成AIへ渡すことも避けます。説明の表が必要なら、架空の内容で独立して作成したことを明記できます。

応募する場合も、現職の勤務と私用の準備を分けます。面接の日時は所属の休暇等の手続きを確認して調整できます。退職を先に決める必要はなく、現職で経験を続けながら、仕事内容や条件の合う募集を調べる選択も残せます。

確認事項をまとめたい方は、[LINEで職務や条件を短く整理することもできます](https://line.me/R/ti/p/@697nxhbt)。応募前の情報収集としても利用できます。

## よくある質問

### 業界未経験ならどの職種にも応募できますか

業界未経験と、職務や資格の条件は別です。今回のLIXILの営業は営業経験と免許を必須とし、建材等の営業経験を歓迎しています。TOTOの開発職も業種不問ですが本人の開発や実装の実務が必要です。今回の個別募集と本人の事実を照合します。

### 公務での施設担当は開発の経験になりますか

担当した内容によります。要望の整理、発注、連絡、納品の確認と、自分で設計や実装を行ったことは別です。部署で行った仕事の全体を自分の経験にせず、本人の工程と委託先や技術担当の工程を分けて説明できます。

### 応募のために先に退職した方がよいですか

この記事は退職を勧めるものではありません。在職中に職務や必須条件、勤務地や契約を比較できます。現職を続ける判断も等しく扱えます。学習を始める場合も、資格や学習だけで採用が保証されるとは考えず、希望する仕事との関係を確認します。
