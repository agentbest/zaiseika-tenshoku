実績をまとめた資料は、勤務先の資料を集めた作品集にする必要はありません。応募先が知りたい工程に沿って、本人が行ったこと、他者が判断・制作したこと、説明できない情報を分けて整理します。見栄えよりも、本人の担当範囲が誤解なく読めることを優先しましょう。

本記事は2026年11月時点の公開情報にもとづきます。確認日は2026年11月24日です。資料の提出可否、個別の情報の外部利用、応募要件への適合や採用を保証するものではありません。

## まず必要な資料と提出方法を確認する

応募先が資料を求めているか、何を確認したいかを最初に読みます。職務経歴書で足りる場合と、制作物や補足資料を指定される場合では、準備するものが違います。形式、容量、提出経路、閲覧者、提出期限等に不明点があれば、担当者へ確認します。

指定がないのに大きな資料を送り、読まれることを前提にしないようにします。補足資料を添付できるか、内容を説明する機会があるかを聞き、必要な範囲へ絞ります。応募先から求められた場合でも、所属の規程や第三者の権利に反する情報を出せるようになるわけではありません。

資料の目的は、本人が担当した仕事を理解するための補足です。採用されるための特別な形式があると考えるより、募集に書かれた業務と対応する工程が読めるかを確かめます。公開されていない選考基準や評価の配点を推測して作り込む必要はありません。

具体的な募集との接点を探したい場合は、[公務員の経験から検討できる求人一覧](../?gov=1)も参照できます。資料の有無だけで応募先を選ばず、仕事内容と本人の希望する働き方を並べて確認してください。

## 本人の作業と他者の成果物を分ける

一つの案件でも、企画、資料確認、意思決定、制作、検証、運用の担当は異なります。本人が委託先と連絡した経験と、委託先が制作した図表やシステムを本人が作った経験は別です。承認された資料を更新したことと、内容の方針を自ら設計したことも分けます。

記載する項目は、背景のうち説明可能な範囲、本人の役割、行った工程、他者の役割、作ったもの、結果の確認範囲にすると整理できます。組織全体の結果を載せる場合でも、その結果を本人だけの成果と読める書き方にしません。公開情報の結果であることと本人の貢献は別に説明します。

効果を測定していない仕事は、未計測と残します。期限内に資料を渡した、変更箇所を確認した、質問事項を整理したといった実施した工程が説明できれば、その範囲を記します。削減時間、満足度、売上等を後から推定して実績として加える必要はありません。

学習のために作った表や説明資料は「学習用の作例」と明記します。実務で使用した成果物ではないこと、実在の組織の課題を解決した結果ではないことを残してください。学習用のデータも、内部データを持ち出して作るのではなく、利用条件を確認できる公開データや独立した架空の題材を使います。

:::insight
実績資料では、完成した見た目から本人の役割を逆算しないことを勧めます。組織が公表した資料に関わっていても、本人が担当した確認や連絡と、専門職や委託先が制作した部分は別です。本人の工程が読めるように役割を添え、最終判断の権限まで持っていたような説明は避けましょう。効果を測っていなければ、数字を作らず、何を作り、誰へ確認し、どこまで実施したかを示せます。学習用の作例も、その区分を明記すれば実務経験と混同せず提示できます。資料の量より、本人が説明できる範囲と、読み手が追加で確認したい点が分かる構成を重視してください。現職で続けたい工程の整理にも使えます。
:::

## 内部資料は匿名化だけで利用できない

資料から名前や金額を消せば外部へ出せる、とは考えません。記載内容の組み合わせから案件が分かる場合もあり、情報の取扱規程、守秘、個人情報、著作権等の確認は別に必要です。勤務先の内部資料を個人端末へ移し、そこから匿名化する方法を選ばないでください。

地方公務員法第34条、国家公務員法第100条は、それぞれ対象となる職員の職務上の秘密を守る義務を定め、退職後にも継続する旨を規定しています。内部資料のすべてが同じ法的な秘密に当たると決めつけるのではなく、扱う情報の性質と所属の規程を確認します。判断がつかない内容は外部へ出さず、所属の適切な窓口へ確認します。

本人が作成に関わったからといって、自由に転載できるとは限りません。文化庁の著作権契約マニュアルは、利用許諾には利用方法や条件の範囲があることを説明しています。ある用途の利用が認められていることを、応募資料への転載やインターネット公開の許可として扱わないようにします。

公開済みの図表や写真も、公開されている事実だけで再利用可能とは判断しません。権利者、利用条件、提出先や公開範囲を確認します。委託先へ制作を依頼したこと、報酬を払ったこと、納品を受けたことだけから、本人が権利を持つと結論づけないでください。個別の権利関係が不明なものは載せない選択ができます。

## 独立した説明資料の記入例

次は構成を示すために新しく作成した、独立した架空の資料例です。実在の案件や内部資料の再現ではなく、実際の職員、相談事例、成果や採用結果を示しません。本人の資料へ応用する場合は事実へ置き換え、実施していない工程は削除してください。架空の作業を本人の実績として記載する用途には使いません。

| 項目 | 架空資料の記入内容 |
|---|---|
| 表題 | 部署からの回答を確認する工程の説明 |
| 資料の区分 | 書き方を説明するための架空例。実務で用いた資料やその抜粋ではない |
| 説明する対象 | 複数部署から届く回答の提出状況と不足項目を確認する事務 |
| 架空例で本人が担当したこと | 提出状況の一覧を作り、未記入欄を確認し、担当部署へ確認事項を伝えた |
| 判断の分担 | 回答の方針と例外対応は責任者が判断。本人は確認点を整理して報告 |
| 本人が作ったもの | 提出状況の確認用一覧と、責任者へ渡す確認事項のメモ |
| 他者が担当したこと | 各部署の回答作成、責任者の内容判断、最終的な回答の確定 |
| 結果として記す範囲 | 一覧とメモを作成して確認を依頼した工程。時間短縮等の効果は未計測 |
| 含めないもの | 実在の部署名、担当者名、案件、内部の回答文、未公表の判断内容 |
| 応募先に聞くこと | 同様の職務では、進行確認に加えてどの判断や施策実行を担うか |

この例には、実在の回答や処理件数を載せていません。実際の資料を小さく印刷して貼る代わりに、工程を文章で説明する構成です。本人の経験へ置き換える際にも、外部へ説明してよい内容だけを用い、確認できない記録を補わないでください。

資料の作成目的と区分は、表紙だけでなく該当するページにも示します。学習用の作例を同じファイルへ入れるなら、実務の説明と見分けられる見出しを付けます。作例を本番で使った実績のように読ませないことが大切です。

職務のまとめ方を相談したい場合は、[面談の申込案内](../apply.html)を確認できます。ご利用は無料です（紹介手数料は採用企業の負担）。経験や希望条件等によっては面談・求人紹介をご案内できない場合があります。相談時にも、内部資料や第三者の情報を送付する必要はありません。

## 募集の工程と資料の内容を照合する

確認したHacobuの経営企画の個別募集には、業務の可視化、施策の実行、運用の定着等が示されています。資料を作るときは、このような仕事内容を工程に分け、本人が説明できる範囲と、経験がない範囲を並べます。

例えば、状況一覧を作った経験は、その工程として示せます。しかし、それだけで業務改革の企画から実装まで主導した経験にはなりません。個別募集の必須要件には主体的な推進やプロジェクトの完遂等も含まれているため、資料の一部が近いことと応募要件全体への適合は別に判断します。

説明する材料が少ない場合でも、実務経験を水増しして埋める必要はありません。応募先が必要とする工程を確認し、現職で経験を深めるか、学習用の作例を作るか、別の募集を比較するかを考えられます。作例を作ったことで実務要件を満たすと決めつけないようにしてください。

:::insight
資料の最終確認では、提出してよい内容かと、担当範囲が正確かを別々に読みます。公開済みの成果物でも本人の制作物とは限らず、本人が作ったものでも自由に外部へ出せるとは限りません。権利や取扱いの確認が終わらない素材は載せず、説明可能な工程から構成しましょう。きれいな図を追加するより、本人と他者の役割、実務と学習、計測済みと未計測を区別することが先です。応募先が求める範囲も確認し、必要のない添付を増やさないようにします。転職のためだけに成果を作り直すのではなく、現職を続ける場合も含め、今後担当したい仕事を具体化する資料として扱うことを勧めます。
:::

## 提出前に内容と送付先を読み合わせる

送る前に、職務経歴書と本人の役割が一致しているか、数字に根拠があるか、架空例や学習用の作例の区分が残っているかを確認します。共有先、リンクの閲覧範囲、ファイル名や作成者情報等も確認し、必要な相手に必要な範囲で提出します。公開リンクを作ったから安全になるわけではありません。

外部の生成AIへ内部情報や個人情報を入力して文章や図に変換することも避けます。作成を補助する道具を使っても、情報を出せるかの判断や成果の事実性の確認が不要になるわけではありません。迷う素材を削除しても、説明できる本人の工程が残る構成を選びましょう。

相談方法を確認したい場合は、[LINEの案内](https://line.me/R/ti/p/@697nxhbt)も利用できます。資料そのものを送る前に、目的と相談範囲を整理してください。応募を急がず、現職で続けたい仕事と並べて検討することもできます。

## よくある質問

### 内部資料の名前を消せば提出できますか？

匿名化だけでは判断できません。内容の組み合わせ、守秘、個人情報、権利、所属の取扱規程等を確認します。不明なものは持ち出したり送付したりせず、適切な窓口へ確認してください。

### 委託先が作った資料を本人の作品として出せますか？

他者の制作物を本人の制作実績にしません。本人が担当した依頼、連絡、確認等の工程は分けて説明できます。素材の転載や利用の可否も、権利と利用条件を別に確認します。

### 学習用の作例しかない場合はどうしますか？

学習用であること、実務で利用した成果物ではないことを明記します。応募先が求める経験や提出物に合うかも確認してください。作例の制作だけで実務経験の要件を満たしたとは扱いません。
