志望動機を書くとき、**いちばん時間がかかるのが接点探し**です。

**「自分の経験が、この会社のどこで使えるのか分からない」**

この状態で書くと、**抽象的な文章になります。**「調整力を活かして」「培った経験を活かして」。**どこで使うのかが書かれていません。**

この記事では、**接点を探す手順**を扱います。志望動機の組み立ては[公務員からの転職で志望動機をどう組み立てるか](senko-shibo-kihon.html)にあります。

## 役所の仕事は、民間も担っています

**接点があるかどうかは、制度の側からも確認できます。**

**地方自治法第244条の2第3項**です。

> 普通地方公共団体は、公の施設の設置の目的を効果的に達成するため必要があると認めるときは、条例の定めるところにより、**法人その他の団体であつて当該普通地方公共団体が指定するもの**（中略）に、**当該公の施設の管理を行わせることができる。**

**公の施設の管理を、指定した法人に行わせることができる。**

**指定管理者の制度**です。**役所が直接やっていた施設の管理を、民間の法人が担う仕組み**が、法律に定められています。

**つまり、役所の仕事と民間の仕事は、制度の上でも地続き**です。

**施設の管理だけではありません。**業務の委託、指定管理、発注者支援、システムの導入。**役所の業務の相当部分に、民間の担い手がいます。**

**接点は、探せばあります。**

## 接点の4類型

| 類型 | 内容 | 例 |
|---|---|---|
| ① 同じ顧客 | **相手が同じ**（自治体、住民、事業者） | 自治体向けのシステム、発注者支援 |
| ② 同じ機能 | **やることが同じ**（審査、調達、債権の管理） | 金融の審査、企業の購買、債権の回収 |
| ③ 同じ制度 | **扱う制度が同じ**（介護保険、建築基準、廃棄物） | 介護の事業者、建設会社、廃棄物の処理 |
| ④ 同じ困りごと | **解決する課題が同じ** | 業務の標準化、人手不足への対応 |

**①から④の順に、説明しやすくなります。**

**①は、説明が要りません。**「顧客が自治体なので、これまでの相手と同じです」で伝わります。

**④は、抽象度が上がるため、具体を足す必要があります。**

## 探す手順

| 順 | やること |
|---|---|
| 1 | 求人票の「仕事内容」を1行ずつ読む |
| 2 | 各行について、**自分が似たことをした場面**を探す |
| 3 | 見つかった場面を、**①〜④のどれか**に分類する |
| 4 | **いちばん具体的に書ける1つ**を選ぶ |
| 5 | その場面を、数字を入れて3行で書く |

**2つ目が作業の中心です。**

**「似たこと」の基準は、完全一致ではありません。**

**相手が違っても、やることが同じなら接点**です。事業者への指導と、委託先の管理。**相手は違いますが、やることは同じ**です。

## 求人票から逆算する

**求人票の言葉を、自分の経験に置き換えてみてください。**

| 求人票の言葉 | 対応する役所の経験 |
|---|---|
| 「顧客の課題のヒアリング」 | 事業者や住民からの相談、要望の聞き取り |
| 「提案資料の作成」 | 議会や審議会の説明資料、事業の企画書 |
| 「関係部署との調整」 | 庁内の協議、合議、他課との折衝 |
| 「業務フローの改善」 | 様式の統一、手順書の作成、集計の自動化 |
| 「委託先の管理」 | 事業者への指導、契約の履行の確認 |
| 「予算の管理」 | 予算の要求、執行の管理、決算 |
| 「制度の調査」 | 法令と通知の確認、他団体の例の調査 |

**この表の右側は、すべて役所の日常業務**です。

**左側の言葉で求人を探すと、見える求人が変わります。**

## 接点が見つからない場合

**3つの理由が考えられます。**

| 理由 | 対処 |
|---|---|
| 求人票の読み込みが浅い | **1行ずつ読む。**まとめて読むと接点が飛びます |
| 自分の経験の棚卸しができていない | **担当した機能を3つ書き出す** |
| 本当に対応していない | **その求人は見送る** |

**2つ目が、実際にはいちばん多い**です。

**自分の経験を「税務課3年、市民課2年」と部署で覚えていると、接点が探せません。**

**「債権の管理と回収」「申請の審査」と機能で持っておくと、照合できます。**

**棚卸しの方法は**[公務員の職務経歴書｜民間で読まれる形にする基本](senko-shokumu-kihon.html)**にあります。**

:::insight
接点を探すときに、**面談でよく使う質問が「その仕事、誰が困っていて、何を解決しましたか」**です。業務の名前で考えると接点が見つかりませんが、**困りごとで考えると見つかります。**たとえば、滞納整理。**業務の名前で考えると「税務」ですが、困りごとで考えると「支払われるはずのものが支払われていない」**です。**この困りごとは、民間のあらゆる業種にあります。**通信、医療、不動産、金融。**どこにでも未収金があります。**同じように、窓口の案内は「制度が複雑で、利用者が分からない」という困りごとへの対応です。**これも、保険、金融、行政手続の支援など、多くの業種にあります。**業務の名前は業界ごとに違いますが、**困りごとは共通していることが多い。**接点が見つからないときは、**「何を解決していたか」に言い換えてみてください。**ご利用は無料です（紹介手数料は採用企業の負担です）。
:::

## 業界別に、接点が生じやすい部分

**応募先の業界によって、どの類型の接点が立ちやすいかが変わります。**

| 業界 | 立ちやすい接点 |
|---|---|
| 自治体向けのシステム | ①同じ顧客、④業務の標準化という困りごと |
| 建設コンサルタント・発注者支援 | ①同じ顧客、②発注と監督の機能 |
| 医療・福祉・介護の事業者 | ③同じ制度（保険や基準）、②審査と記録の機能 |
| 金融・保険 | ②審査と債権の管理の機能 |
| 不動産・施設の管理 | ②用地と施設の管理の機能、③建築や消防の基準 |
| 人材・研修 | ②説明と育成の機能、④人手不足という困りごと |
| 製造・物流 | ②品質と記録の管理の機能、③許認可や基準 |

**表の右側が、志望動機の②に書く材料**になります。

**自分の経験と照らして、重なる行がある業界から見ていく**と、探す範囲が絞れます。重なる行が無い業界は、**接点の説明が長くなるため、優先順位を下げて構いません。**

## 接点は、1つで足りる

**複数挙げる必要はありません。**

| 接点の数 | 印象 |
|---|---|
| 1つを具体的に | **その経験が使えると伝わる** |
| 3つを抽象的に | どれも印象に残らない |

**1つ選んで、数字を入れて3行で書く。**これが、いちばん効きます。

> 基幹システムの更改にあたり、業務側の担当として現行の帳票◯種類と例外の処理◯類型を棚卸ししました。稼働後は職員向けの手順書を作成し、問い合わせ約◯件に対応しています。御社の導入の支援でも、同じ工程があると理解しています。

**接点が1つ具体的に書けていれば、志望動機は成立します。**

[経験の言い換えから相談する](../apply.html)こともできます。

## よくある失敗

**1. 求人票をまとめて読む**

**1行ずつ**読んでください。

**2. 完全一致を探す**

**相手が違っても、やることが同じなら接点**です。

**3. 部署名で経験を覚えている**

**機能で持っておく**と照合できます。

**4. 接点を3つ以上挙げる**

**1つを具体的に**書いてください。

**5. 数字を入れない**

**規模が分かると、接点の信頼性が上がります。**

**6. 見つからないまま応募する**

**見送る判断**もあります。

:::insight
ここまで探し方の話をしておいて逆のことを言いますが、**接点は、応募先ごとに探し直す必要がありません。**自分の経験の棚卸しを1回やっておけば、**あとは求人票と照合するだけ**です。面談で拝見していると、**応募先が変わるたびに、ゼロから考え直している方**がいらっしゃいます。時間がかかるのは当然です。対処としては、**自分の機能を3つ、それぞれ「規模・判断した範囲・変えたこと」を添えて書き出しておく**ことです。**これが、接点探しの共通の材料**になります。応募先ごとにやるのは、**「この3つのうち、どれがこの求人と重なるか」を選ぶ作業だけ**です。**1社あたり15分で済みます。**棚卸しに3時間かけておけば、**その後の応募がすべて楽になります。**在職中でも、情報収集だけでも構いません。
:::

## まとめ

- **地方自治法第244条の2第3項**は、**公の施設の管理を指定した法人に行わせることができる**としています。**役所の仕事と民間の仕事は、制度上も地続き**です
- 接点は、**①同じ顧客 ②同じ機能 ③同じ制度 ④同じ困りごと**の4類型で探します
- 手順は、**求人票を1行ずつ読み、似た場面を探し、分類し、1つ選ぶ**です
- **完全一致を探さない。**相手が違っても、やることが同じなら接点です
- **接点が見つからないときは、「何を解決していたか」に言い換えて**ください
- **接点は1つで足ります。**数字を入れて3行で書いてください

行政が相手の求人もまとまっています。[行政が相手の求人を見てみる](../?gov=1)。

## よくある質問

### 内部管理の部門にいて、外部との接点がありません

**内部の仕事にも、接点はあります。**人事、財政、契約、法制、情報システム。**これらは、民間の管理部門とほぼ同じ機能**です。人事なら、採用、評価の運用、研修。財政なら、予算の編成と執行の管理。契約なら、調達とベンダーの管理。**相手が社内になるだけで、やることは同じ**です。加えて、**自治体向けの事業をしている会社では、庁内の意思決定の流れを知っていること自体が価値**になります。「決裁がどう回るか」「予算がいつ決まるか」。**内部にいた人のほうが詳しい部分**です。接点は、**社外との折衝だけではありません。**

### 技術職ですが、応募先が事務系の職種です

**工程で接点を探してください。**技術職の仕事は、**計画・設計・発注・監督・維持管理**に分かれます。このうち、**発注と維持管理は、事務的な要素が大きい**部分です。積算、契約、工程の管理、予算の執行。**これらは、事務系の職種と重なります。**また、**図面や数量を扱ってきた経験は、数字を扱う仕事全般に対応します。**書くときは、**「技術職ですが」と前置きしないでください。**担当してきた工程のうち、**応募先に対応する部分**を出せば足ります。

### 接点はあるが、規模が小さくて書きにくいです

**規模は、そのまま書いて構いません。**大きく見せる必要はありません。**面接で確認されて崩れるほうが問題**です。むしろ、**小さい規模でも、一貫して担当していれば、工程の全体を知っている**という強みになります。大規模な事業は分業になるため、**一部の工程しか経験しないことがあります。**書くなら、**「年間約◯件について、受付から決定まで一貫して担当」**という形です。**一貫性は、規模とは別の価値**です。数字の出し方は[数字で書けない仕事を、数字で書く方法](senko-shokumu-suji.html)に整理しています。
