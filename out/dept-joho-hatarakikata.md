情報政策課・DX推進の働き方には、はっきりした特徴があります。

**成果が、自分の部署には出ません。**

効率化されるのは各課の業務で、便利になるのは住民の手続です。情報政策課に残るのは、**止まったときの対応**のほうです。

この構造を知っておくと、自分の仕事をどう説明すればよいかが決まりますし、民間に移ったときに何が変わるかも見通せます。

この記事では、その構造を条文から確認したうえで、一年の波と評価のされ方、そして移ったあとに変わることを扱います。

言い換えは[情報政策課・DX推進の経験は民間で何と呼ばれるか](dept-joho-honyaku.html)、行き先は[情報政策課・DX推進からの転職先](dept-joho-tenshokusaki.html)、書類と面接は[職務経歴書](dept-joho-shokumu.html)と[面接](dept-joho-mensetsu.html)に分けています。

## 目的が2つあり、どちらも自分の部署には出ません

番号法第3条は基本理念を列挙しており、第1号がこうです。

**行政事務の処理において、個人又は法人その他の団体に関する情報の管理を一層効率化するとともに、当該事務の対象となる者を特定する簡易な手続を設けることによって、国民の利便性の向上及び行政運営の効率化に資すること。**

第2号では、**情報提供ネットワークシステムその他これに準ずる情報システムを利用して迅速かつ安全に情報の授受を行い、情報を共有すること**によって、社会保障制度、税制その他の行政分野における給付と負担の適切な確保を図る、という趣旨が続きます。

目的が2つ並んでいます。

**国民の利便性の向上。そして、行政運営の効率化。**

どちらも大事ですが、**どちらも情報政策課の数字としては現れません。**

利便性が上がったかどうかは、住民の手続の側に出ます。効率化されたかどうかは、各課の業務の側に出ます。情報政策課に残るのは、**システムが止まったかどうか**だけです。

**動いて当たり前。止まると問われる。**これがこの部署の評価の構造です。

## 情報政策課の一年

自治体によって時期は違いますが、おおむね次の流れになります。

| 時期 | 主な仕事 |
|---|---|
| 4月 | **年度切替（第1の山）**。制度改正の反映、人事異動に伴う権限の設定、新年度の稼働確認 |
| 5〜7月 | 各課からの改修要望の受付、次年度に向けた見積りの依頼 |
| 8〜9月 | **予算要求（第2の山）**。要望を積算し、財政課と協議 |
| 10〜12月 | **調達（第3の山）**。仕様書の作成、入札、事業者の決定 |
| 1〜3月 | **制度改正への対応と年度末の稼働準備（最大の山）**。データ移行、稼働前の検証 |
| 通年 | 障害対応、セキュリティ研修、個人情報の審査、事業者との定例協議 |

**山が4回あります。**そして、それぞれ性質が違います。

年度切替は**動かせない期限**、予算要求は**財政課の日程**、調達は**契約の手続**、年度末は**制度改正の施行日**です。どれも自分では動かせません。

さらに、数年に一度**基幹システムの更改**が通年で上に乗ります。この年度は、ほかの仕事が変わらないまま作業が増えます。

そして、**障害はいつ来るか分かりません。**計画の外で時間が消える仕事が、常に一定量あります。

## 転職活動の時期を、この波から逆算する

面接は平日日中に入ることが多く、1社で複数回あります。**1月から4月は避けたほうが無難**です。制度改正の施行日と年度切替が重なり、止められない作業が集中します。

比較的まとまった時間を作りやすいのは、**5月から7月**です。年度切替が落ち着き、予算要求が本格化する前の時期にあたります。

現実的な組み立てはこうなります。

1. 年度切替が片付いた5月に書類を作る
2. 5月から7月に2社ほど受けて、説明の詰まる場所を直す
3. 8月から12月は予算要求と調達があるので、進んでいる1社だけに絞る
4. 年度末は止めて、翌年度の5月に再開する

**更改が進行中の場合は、稼働を見届けてから動く判断にも十分な理があります。**途中で抜けると「関わった」としか書けませんが、通せば「調達から稼働まで一貫して担当した」と書けます。

## 評価が扱いにくい3つの理由

**1. 成果が他部署に出る**

上に書いたとおりです。効率化されたのは各課の業務で、その実績は各課のものになります。

**2. 止まったときだけ名前が出る**

稼働している間は誰も情報政策課の話をしません。障害が起きた日だけ、全庁から問い合わせが来ます。

**3. セキュリティの成果は「何も起きなかったこと」**

事故が起きなければ、何もしていないように見えます。**起きたときには、対策が足りなかったと言われます。**

この3つは、**不満として語らないでください。**転職の面接でこれを不満の形で出すと、次の職場でも同じことを言うと思われます。

**構造として説明してください。**「成果が他部署に出る前提で、止めないことを仕事にしていた」と言えれば、それはそのまま情報システム部門の適性として読まれます。民間の情報システム部門も、まったく同じ構造だからです。

## 庁内の言葉と、求人票の言葉

働き方に関わる部分を置き換えると、次のようになります。

| 庁内での言い方 | 求人票での言い方 |
|---|---|
| 年度切替の対応 | 期初の切替作業、マスタ更新 |
| 制度改正への対応 | 法令改正対応、リリース管理 |
| 予算要求と見積りの取りまとめ | 予算策定、投資計画の立案 |
| 調達（仕様書・入札・契約） | RFP作成、ベンダー選定、調達 |
| 障害対応 | インシデント管理、障害対応 |
| 事業者との定例協議 | ベンダーマネジメント、運用管理 |
| 各課からの要望の受付 | 要件管理、利用部門対応 |

このうち、働き方として直接伝わるのは**「法令改正対応」**と**「インシデント管理」**です。民間でも、法改正に合わせたリリースと、止まったときの対応は避けて通れません。**そこを回してきた経験として説明すると通りやすくなります。**

[行政が相手の求人を見てみる](../?gov=1)

:::insight
この部署の方が民間に移って最初に戸惑うのは、**「止まったときの影響が金額で出ること」**です。自治体では、システムが止まると窓口が止まり、住民が待ちます。これは深刻ですが、**金額としては表れません。**事業会社では、止まった時間がそのまま売上の損失として計算されます。**同じ障害でも、話の重さが変わります。**一方で、これは有利にも働きます。金額が出るぶん、**対策に予算がつきやすくなる**からです。自治体では「起きていないこと」への予算は通りにくい。面接では「直近で大きな障害はありましたか」「そのあと体制は変わりましたか」と聞いてみてください。**答え方で、その会社が止まることをどう扱っているかが分かります。**
:::

## 民間に移ると、何が変わるか

**1. 止まったときの影響が金額で出る**

上に書いたとおりです。**対策に予算がつきやすくなる**という面もあります。

**2. 予算の周期が変わる**

自治体は単年度で、期中の追加には補正予算が要ります。企業でも予算はありますが、**期中に判断が変わることが自治体より多くなります。**「決めたものを動かさない」という進め方から、切り替えが要ります。

**3. 利用部門を選べる場合がある**

自治体では全部署が対象で、断るという選択がありません。企業では、**優先する部門を経営が決める**ことがあります。全部を等しく扱わなくてよい、という状況に慣れが要ります。

**4. 開発の速さが変わる**

内製の会社に入った場合、**調達の手続を経ずに作れる**ようになります。速さは上がりますが、**「あとから直せる前提」で要件が甘くなることもあります。**行政で身につけた「詰め切る」進め方は、ここで効きます。

## 在職中から残しておくとよい記録

評価の構造は変えられませんが、**記録の残し方は自分で決められます。**

**1. 案件ごとの規模**

契約金額、対象業務数、関係する課の数、移行データの件数。**あとから調べるのは難しくなります。**

**2. 止まったときの対応**

いつ、何が起き、どう切り分け、何日で復旧し、その後どう変えたか。**この経歴でいちばん読まれる材料です。**

**3. 受けなかった要望**

何件受けて、何件断ったか。断った理由は何か。**断り方を持っている人は多くありません。**

**4. 残した手続と、その理由**

オンライン化で置き換えられなかったもの。**業務改革の方向を狙うなら、これが中心の材料になります。**

## つまずきやすい点

**1. 年度末から4月に活動を始めて中断する**

いちばん多い形です。**5月以降から始めてください。**

**2. 忙しさを転職理由にする**

情報システム部門は民間でも繁忙期があります。**理由は、やってきたことの延長で組んでください。**

**3. 評価されにくさを不満の形で出す**

構造として説明すれば強みになり、不満として出すと弱みになります。**同じ事実でも、置き方で逆になります。**

**4. 更改の途中で動く**

稼働まで通すと、書けることが大きく変わります。**「関わった」と「一貫して担当した」では、読まれ方が違います。**

**5. 異動の可能性を検討しないまま動く**

情報政策課は、企画課、総務課、市民課、税務課のいずれとも接続します。**庁内で移る選択肢を一度も検討していないなら、先にそちらを確かめたほうが選択肢は減りません。**

**6. 退職時期の制度面を確認しないまま決める**

退職手当や共済の扱いは在職期間で変わる部分があります。**手続きの前に、必ず所属の人事担当課と共済組合で確認してください。**公務員には雇用保険が適用されないため、辞めてから探すと収入のない期間がそのまま持ち出しになります（[公務員に雇用保険がない理由](seido-shitsugyo-nashi.html)）。

自分の場合にどの時期が動きやすいかは、一度話しながら整理したほうが早いことが多いです。[どの経験に値が付くのかから相談できます](../apply.html)。

:::insight
ここまで時期の話をしておいて逆のことを言いますが、**「更改が終わったら動く」と考えていると、動かないまま数年たちます。**基幹システムの更改が終われば、次は標準化への対応、その次はまた別の制度改正が来ます。**完全に区切りがつく瞬間は来ません。**実際に動いた方に共通しているのは、**年度切替が終わった5月に「書類を作る」「2社受ける」といった小さい単位で区切って進めた**ことです。全部を一気にやろうとすると、次の山に飲まれて止まります。逆に、いま更改の真ん中にいるなら、無理に始める必要はありません。**稼働まで通してから動くほうが、書ける材料は確実に厚くなります。**在職中でも、情報収集だけでも構いません。ご利用は無料です（紹介手数料は採用企業の負担です）。
:::

## まとめ

- 番号法第3条は、**国民の利便性の向上**と**行政運営の効率化**の2つを基本理念に挙げています。**どちらも情報政策課の数字としては現れません**
- 利便性は住民の側に、効率化は各課の側に出ます。情報政策課に残るのは**止まったかどうか**だけです
- 山は**年度切替（4月）／予算要求（8〜9月）／調達（10〜12月）／制度改正と年度末（1〜3月）**の4回。加えて数年に一度、更改が通年で乗ります
- 活動しやすいのは**5月から7月**です。年度切替が落ち着き、予算要求が本格化する前の時期にあたります
- 評価が扱いにくい理由は**成果が他部署に出る／止まったときだけ名前が出る／セキュリティの成果は何も起きなかったこと**の3つ。**不満ではなく構造として説明してください**
- 民間に移って最初に戸惑うのは、**止まったときの影響が金額で出ること**です。対策に予算がつきやすくなる面もあります

## よくある質問

### 情報政策課は残業が多いと聞きますが、実際どうですか

自治体ごとの実態は公表されていないので、個別の水準をここで断定することはできません。**制度から言えるのは、年度切替・予算要求・調達・制度改正という4つの山が制度の日程で決まっていて、加えて障害が計画の外で発生する構造**だということです。応募先に説明するときは、時間数ではなく**「山が年4回あって、そのうえ計画外の対応が一定量ある部署でした」**と構造で伝えるほうが正確に伝わります。

### システムが止まった経験は、書いても面接で話してもよいですか

**話してください。**ただし、**どのシステムで何が起きたかの技術的な詳細は避け、対応の形で話す**のが安全です。「稼働直後に特定の条件で不具合が出た」「業務側の回避手順を先に決めた」「事業者と原因を切り分けた」「検証項目に追加した」という形なら、在職中の団体の情報に踏み込まずに済みます。**止まった事実そのものは、隠すより話したほうが評価されます。**

### 更改を担当していない場合、経験が弱くなりますか

方向によります。**情報システム部門や自治体向け企業を狙うなら、更改を通したかどうかは効きます。**一方、**業務改革の方向では、日々の運用のなかで何をどう変えたかで勝負できます。**オンライン化で残した手続と理由、要望の断り方、規程を守れる形に直した話。**どれも更改とは別の材料です。**方向の選び方は[情報政策課・DX推進からの転職先](dept-joho-tenshokusaki.html)に整理しています。
