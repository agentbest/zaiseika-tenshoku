**自治体のシステムに関わってきた方から、「支援する側に移れるか」**というご相談を伺います。

**役割分担の原則が、法律に置かれています。**

この記事では、**その構造**と、**資格の位置づけ**を扱います。

**⚠ 試験の内容・区分・実施の方法は、所管するところの公表を確認してください。****この記事では、個別の内容には触れません。**

## 民間が主導的役割を担うことが原則です

**デジタル社会形成基本法第9条**です。

> **デジタル社会の形成に当たっては、民間が主導的役割を担うことを原則とし、国及び地方公共団体は、民間の知見を積極的に活用しながら**（略）**民間の活力が十分に発揮されるための環境整備並びに公共サービス**（略）**における国民の利便性の向上並びに行政運営の簡素化、効率化及び透明性の向上**（略）**のための環境整備を中心とした施策を行うものとする。**

**「民間が主導的役割を担うことを原則とし」**と書かれています。

**そして、国及び地方公共団体は「民間の知見を積極的に活用しながら」**施策を行うとされています。

**つまり、行政のシステムは、民間が担うことが前提の構造**になっています。

**自治体向けのシステムやコンサルティングの事業は、この構造の上にあります。**

**そして、そこで求められるのは、行政の側の事情を理解している人**です。

## 発注する側の経験が接続する部分

| 経験 | 支援する側での使いどころ |
|---|---|
| ① 業務の理解 | **現場でどう使われるか** |
| ② 要件の整理 | 各課からの聞き取り |
| ③ 仕様の作成 | 求める内容の記述 |
| ④ 調達の手続 | 予算、選定、契約 |
| ⑤ 受入れの確認 | 完了の条件 |
| ⑥ 運用の定着 | 手順書、研修、問い合わせ |

**①と④が、外から入った人には見えにくい**部分です。

**④について。**

**予算の時期、議会の日程、決裁の流れ、年度の区切り。**

**これらを知らないと、提案の時期を外します。**

**扱いは**[営業の基礎｜行政営業で公務員経験が効く理由](skill-eigyokiso.html)**に整理しています。**

## 資格の位置づけ

| 状況 | 扱い |
|---|---|
| ① 応募条件に記載がある | **満たす材料になる** |
| ② 技術の実務がない | 到達を示すものが他にない |
| ③ 業務側の経験がある | **経験のほうが具体** |
| ④ 用語を揃えたい | 学ぶ意味があります |
| ⑤ 目的が曖昧 | 優先順位を下げてください |

**②と④が、取る理由になります。**

**④について。**

**技術の担当者と話す際に、言葉が通じる**ようになります。

**何ができて、何が難しいかの見当がつくと、要件の整理が速くなります。**

**なお、取れば転職できる、という関係にはありません。**

**何を担当し、どう進めたか**が、評価の対象です。

## 書き方の例

**悪い例**

> システムの担当として、業者とのやり取りをしていました。

**良い例**

> ◯◯システムの更改にあたり、**業務側の担当として、関係する◯課・◯名から業務の状況を聞き取り。**現行の帳票**◯種類を棚卸しし、◯種類に統合。**求める機能と性能を**仕様に記載し、事業者◯者の提案を評価。****受入れの確認の観点を要件ごとに設定。**運用の開始後は、**手順書の作成と職員◯名への研修**を担当。

**「立場」「聞き取りの規模」「棚卸し」「評価」「定着」**が入っています。

**基本の型は**[公務員の職務経歴書｜民間で読まれる形にする基本](senko-shokumu-kihon.html)**に整理しています。**

:::insight
支援する側への転職について、**面談でお伝えしているのが「評価した側にいた経験を書いてください」**という点です。**提案を受け、比較し、選定した。**この経験は、**提案する側に回ったときに、そのまま使えます。**どの資料が読まれ、どの説明が響かなかったか。何が決め手になり、何が減点されたか。**評価する側の基準を知っている**ということです。そして、**多くの担当者は、この基準を推測でしか知りません。**さらに、**デジタル社会形成基本法第9条のとおり、行政のシステムは民間が担うことが前提の構造**です。**支援する側の会社は、行政の事情を理解している人を必要としています。**書類には、**「事業者◯者の提案を評価し、選定の理由を整理」**と書いてください。**技術の深さで勝負しなくても、書ける材料があります。**ご利用は無料です（紹介手数料は採用企業の負担です）。
:::

## 職種の選び方

| 職種 | 求められるもの |
|---|---|
| ① 業務側の担当 | **業務と制度の理解** |
| ② 導入の支援 | 要件の整理、合意の形成 |
| ③ 営業 | 予算と時期の理解 |
| ④ 設計・開発 | 技術の実務 |
| ⑤ 運用・保守 | 運用の設計 |

**①〜③が、経験と重なります。**

**④は、技術の実務が要件になることが多い**です。

**求人票の仕事内容の欄で、どちらを求めているかを確認**してください。

**読み方は**[求人票の読み方｜どこを見れば実態が分かるか](senko-sagasu-kyujinhyo.html)**に整理しています。**

## 書くときの注意

| 注意 | 内容 |
|---|---|
| ① 取得の年を書く | いつ取ったか |
| ② 区分を正確に | **段階がある場合** |
| ③ 立場を明記 | **業務側か、技術側か** |
| ④ できる範囲を限定 | 設計・開発まで含めない |
| ⑤ 実務と併記 | 業務側の経験と組み合わせる |

**③と④が重要**です。

**資格を書いたことで、開発まで担えると受け取られる**ことがあります。

**「業務側の担当として、要件の整理と受入れの確認を担当」**と、**立場を明記**してください。

## 在職中にできること

| 項目 | 内容 |
|---|---|
| 担当の整理 | **聞き取り、仕様、選定、定着** |
| 規模の確認 | 課の数、帳票の数、職員の数 |
| 用語の学習 | 長く続ける前提で |
| 求人を読む | 週に30分 |

**2行目です。**

**年度の報告や決裁の資料から確認**してください。

**根拠のない数は書かないでください。**

[経験の言い換えから相談する](../apply.html)こともできます。

## 面接で聞かれやすいこと

| 質問の趣旨 | 用意しておくこと |
|---|---|
| 担当したシステム | **規模、期間、立場** |
| 要件の整理 | 矛盾する要望の扱い |
| 提案の評価 | **何を見て決めたか** |
| 受入れの確認 | 完了の条件 |
| 立場 | 業務側か、技術側か |

**3行目です。**

**選定の理由を整理した経験**は、提案する側でも使えます。

**なお、特定の事業者が分かる説明は避けてください。**

**守秘の義務は、退職した後も続きます。**

## よくある失敗

**1. 「業者とのやり取り」と書く**

**評価した側にいた**ことを書いてください。

**2. 聞き取りの規模を書かない**

**課の数と人数**を書いてください。

**3. 棚卸しの結果を書かない**

**◯種類を◯種類に**と数で書いてください。

**4. 受入れの確認を書かない**

**完了の条件**を決めた経験です。

**5. 立場を書かない**

**業務側か技術側か**を明記してください。

**6. できる範囲を広く書く**

**設計・開発まで含めない**でください。

**7. 技術の深さで勝負しようとする**

**行政の事情の理解**が求められています。

**8. 取れば転職できると考える**

**何を担当しどう進めたか**が評価の対象です。

:::insight
ここまで「業務側の経験が書ける」という話をしておいて逆のことを言いますが、**入社後に覚えることは多くあります。**面談で拝見していると、**「行政の事情を知っているから大丈夫」と考えて、準備を省いてしまう方**がいらっしゃいます。ところが、**支援する側では、自社の製品やサービスを説明する必要があります。**何ができて、何ができないか。他社との違いは何か。**ここは、入社後に覚える部分**です。また、**複数の自治体を同時に担当する**ことがあり、**団体ごとの違いに対応する必要**も出てきます。規模、体制、規程、進め方。**1つの団体しか知らない状態からは、広げることになります。**面接では、**「行政の事情と制度の理解は持っている。製品の理解と、複数団体への対応は入社後に身につけたい」**と、**分けて話してください。**在職中でも、情報収集だけでも構いません。
:::

## まとめ

- **デジタル社会形成基本法第9条**は、**民間が主導的役割を担うことを原則とし、国及び地方公共団体は民間の知見を積極的に活用**するとしています
- **行政のシステムは、民間が担うことが前提の構造**です。そこでは**行政の事情を理解している人**が求められます
- 接続するのは、**業務の理解、要件の整理、仕様の作成、調達の手続、受入れの確認、運用の定着**です
- **評価した側にいた経験**を書いてください。提案する側でそのまま使えます
- 職種は、**業務側・導入の支援・営業**が重なります。**設計・開発は技術の実務が要件**になることが多いです
- **立場を明記**し、**できる範囲を限定**してください
- **製品の理解と、複数団体への対応は、入社後に覚える部分**として分けて話してください

行政が相手の求人もまとまっています。[行政が相手の求人を見てみる](../?gov=1)。

## よくある質問

### 情報政策の部署にいませんでした

**書けます。**業務の担当として、**システムの更改に関わった、帳票を整理した、操作の手順書を作った**という経験があれば、材料になります。書き方は、**「◯◯業務の担当として、システムの更改にあたり現行の運用を整理し、要件の確認に参加」**という形です。**自治体向けのシステムの会社では、現場でどう使われるかを知っている人**が求められます。情報政策の部署の経験より、**窓口や事務の現場の経験が評価される**場面もあります。扱いは[ノーコードツール｜情報政策の経験を実装側へ](skill-nocode.html)にも整理しています。

### 資格がないと、応募できませんか

**求人の条件によります。**「必須」であれば、資格が要ります。一方、**「業務側の経験」「行政での実務経験」**を挙げる求人では、**資格が必須でないことがあります。**とくに、**自治体を顧客とする事業では、行政の実務経験が要件として挙げられる**ことがあります。判断の目安は、**応募条件の欄**です。なお、**入社後の取得を支援する制度**がある会社もあります。求人票や採用のページで確認してください。**資格の有無で、候補を狭めないでください。**

### 技術の勉強は、どこから始めればよいですか

**目的で分けてください。**用語を揃える目的であれば、**体系的に学ぶ意味があります。**技術の担当者との会話で、**何ができて何が難しいかの見当がつく**ようになります。一方、**設計や開発を職務とするのであれば、範囲が異なります。**なお、**応募の時期が近い場合は、優先順位を下げて**ください。**職務経歴書の作成と、求人を読む作業**のほうが、時期に直接効きます。扱いは[選考スケジュールの組み方](senko-sagasu-schedule.html)に整理しています。**学習は、入社後にも続けられます。**
