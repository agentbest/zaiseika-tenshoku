**情報の管理に関わってきた方から、「経験をどう示せばよいか」**というご相談を伺います。

**この分野には、法律に定められた資格があります。**

この記事では、**位置づけ**と、**経験の示し方**を扱います。

**⚠ 受験・登録の要件と手続は、所管するところの公表を確認してください。****この記事では、個別の要件には触れません。**

## 試験も名称も、法律に定められています

**情報処理の促進に関する法律第6条第1項**です。

> **情報処理安全確保支援士試験**（以下この節において「支援士試験」という。）**は、情報処理安全確保支援士として必要な知識及び技能について行う。**

**同法第24条**です。

> **情報処理安全確保支援士でない者は、情報処理安全確保支援士という名称を使用してはならない。**

**同法第22条**は、**秘密保持義務**を定めています。

> **情報処理安全確保支援士は、正当な理由がなく、その業務に関して知り得た秘密を漏らし、又は盗用してはならない。**

**試験、名称の使用制限、秘密保持義務が、法律に置かれている**ということです。

**民間の団体が実施する資格とは、位置づけが異なります。**

**このため、応募条件で扱われる場面も違います。**

## 自治体での経験は何にあたるか

| 経験 | 民間での読まれ方 |
|---|---|
| ① 規程の整備 | **方針・基準の策定** |
| ② 研修の実施 | 教育、周知 |
| ③ 権限の管理 | アクセスの管理 |
| ④ 事故への対応 | 初動、報告、再発の防止 |
| ⑤ 監査への対応 | 内部統制、是正 |
| ⑥ 調達での確認 | 委託先の管理 |

**①と⑥が、行政ならでは**です。

**①について。**

**規程や要綱を作り、改正してきた経験**は、**方針や基準を作る仕事**にあたります。

**⑥について。**

**委託先に求める条件を仕様に書き、履行を確認した**という経験です。

**扱いは**[契約書の読み方｜自治体の契約実務との差](skill-keiyakusho.html)**にも整理しています。**

## 書き方の例

**悪い例**

> 情報セキュリティの担当をしていました。

**良い例**

> ◯◯課において、**情報の取扱いに関する規程と手順書の整備**を担当。**職員◯名への研修を年◯回実施し、理解の状況を確認。****権限の付与と抹消の手順を整備し、異動・退職時の処理を月次で確認。**委託にあたり、**求める条件を仕様に記載し、履行を確認。**事案が生じた際は、**経緯を整理し、報告と再発の防止の手順を作成。**

**「規程」「研修」「権限」「委託」「事案」**が入っています。

**⚠ 具体の事案が特定される記述は避けてください。****守秘の義務は、退職した後も続きます。**

**基本の型は**[公務員の職務経歴書｜民間で読まれる形にする基本](senko-shokumu-kihon.html)**に整理しています。**

## 資格の位置づけ

| 状況 | 扱い |
|---|---|
| ① 応募条件に記載がある | **満たす材料になる** |
| ② 技術の実務がない | 到達を示すものが他にない |
| ③ 規程・運用の実務がある | **経験のほうが具体** |
| ④ 名称を用いる業務 | 法律に定めがあります |
| ⑤ 目的が曖昧 | 優先順位を下げてください |

**④について。**

**名称の使用制限が法律に置かれている**ため、**名称を用いる場面では、登録が前提**になります。

**⚠ 受験・登録の要件と手続は、所管の公表を確認**してください。

**なお、取れば転職できる、という関係にはありません。**

**何を整備し、どう運用したか**が、評価の対象です。

:::insight
この分野について、**面談でお伝えしているのが「運用を回した経験を書いてください」**という点です。**規程を作ることは、外部に委託してもできます。**ところが、**作った規程が守られる状態にすること**は、簡単ではありません。権限の付与と抹消が滞る、研修が形だけになる、委託先の確認が書面だけで終わる。**これらは、どの組織でも起きています。**行政では、**監査を受けることが制度として決まっているため、運用の記録を残す習慣**があります。異動のたびに権限を見直し、記録を残し、指摘に対応する。**この地道な運用こそが、民間で求められている部分**です。書類には、**「権限の付与と抹消の手順を整備し、異動・退職時の処理を月次で確認」**と書いてください。**規程を作ったことより、回したことのほうが伝わります。**ご利用は無料です（紹介手数料は採用企業の負担です）。
:::

## どの転職先で効くか

| 領域 | 使いどころ |
|---|---|
| ① 自治体向けの事業 | **規程と運用の実情が分かる** |
| ② 情報の管理の部門 | 規程、権限、教育 |
| ③ 内部監査 | 是正、記録 |
| ④ 委託先の管理 | 条件の設定、確認 |
| ⑤ 規制を受ける業種 | 監査への対応 |

**①について。**

**自治体を顧客とする事業では、相手の規程に沿った運用が求められます。**

**どの条件が求められるか、監査で何を見られるか。**

**これは、受ける側にいないと分かりません。**

**探し方は**[公務員経験が活きる求人の探し方](senko-sagasu-kyujin.html)**に整理しています。**

## 書くときの注意

| 注意 | 内容 |
|---|---|
| ① 取得・登録の年 | いつ取ったか |
| ② 登録の状況 | **有効かどうか** |
| ③ 立場を明記 | 規程・運用側か、技術側か |
| ④ できる範囲を限定 | **技術の実装まで含めない** |
| ⑤ 事案は書かない | 特定される記述を避ける |

**⑤が最も重要**です。

**事案の詳細は書かないでください。**

**「経緯を整理し、報告と再発の防止の手順を作成」**という形で、**動作で書いて**ください。

## 在職中にできること

| 項目 | 内容 |
|---|---|
| 整備した規程の整理 | **作った文書の種類** |
| 運用の記録 | 権限、研修、確認の頻度 |
| 要件の確認 | **所管の公表を確認** |
| 求人を読む | 週に30分 |

**3行目です。**

**受験・登録の要件は、実務の経験の年数や内容で定められていることがあります。**

**人づての情報で判断しないでください。**

**2行目について。**

**確認の周期と、確認した件数を残しておいてください。**

**運用を回した証明になります。**

[経験の言い換えから相談する](../apply.html)こともできます。

## 面接で聞かれやすいこと

| 質問の趣旨 | 用意しておくこと |
|---|---|
| 整備した規程 | **種類と、改正の経緯** |
| 運用の頻度 | 確認の周期 |
| 事案への対応 | **手順（詳細ではなく）** |
| 委託先の管理 | 条件、確認の方法 |
| 立場 | 規程・運用側か、技術側か |

**3行目です。**

**「守秘の義務があるため、個別の事案には触れられませんが」**と前置きすれば、**手順の説明はできます。**

## よくある失敗

**1. 規程を作ったことだけを書く**

**回したこと**のほうが伝わります。

**2. 権限の管理を書かない**

**異動・退職時の処理**は運用の中心です。

**3. 委託先の確認を書かない**

**条件の設定と履行の確認**は経験です。

**4. 事案の詳細を書く**

**動作で書いて**ください。

**5. 立場を書かない**

**規程・運用側か技術側か**を明記してください。

**6. 登録の状況を確認しない**

**有効かどうか**を確認してください。

**7. 要件を人づてで判断する**

**所管の公表**を確認してください。

**8. 取れば転職できると考える**

**何を整備し運用したか**が評価の対象です。

:::insight
ここまで運用の話をしておいて逆のことを言いますが、**技術の理解が不要というわけではありません。**面談で拝見していると、**規程と運用の経験だけで技術側の求人に応募し、面接で具体を問われて止まる方**がいらっしゃいます。**「なぜこの条件が必要なのか」を説明できないと、運用は形だけになります。**権限を分ける理由、記録を残す理由、経路を限る理由。**これらは、仕組みの理解があって初めて説明できます。**そして、**自治体を顧客とする事業では、相手に説明する場面**が出てきます。ですから、**規程・運用の経験を軸にしつつ、仕組みの理解を足す**という順序にしてください。**資格の学習は、この理解を体系的に得る手段**として使えます。**取得そのものを目的にせず、説明できるようになることを目的に**してください。在職中でも、情報収集だけでも構いません。
:::

## まとめ

- **情報処理の促進に関する法律第6条**は**試験**を、**第24条**は**名称の使用制限**を、**第22条**は**秘密保持義務**を定めています
- **民間の団体が実施する資格とは、位置づけが異なります**
- 自治体での経験は、**規程の整備、研修、権限の管理、事故への対応、監査への対応、調達での確認**にあたります
- **規程の整備と、調達での確認**が、行政ならではの材料です
- **規程を作ったことより、運用を回したこと**を書いてください
- **事案の詳細は書かないでください。**動作で書いてください
- **仕組みの理解を足して**ください。説明できることが目的です

行政が相手の求人もまとまっています。[行政が相手の求人を見てみる](../?gov=1)。

## よくある質問

### 技術の担当ではありませんでしたが、書けますか

**書けます。**規程の整備、研修の実施、権限の管理、委託先の確認。**これらは、技術の担当でなくても担っている**ことがあります。書き方は、**「情報の取扱いに関する規程と手順書の整備を担当」「権限の付与と抹消の手順を整備」**という形です。**動作で書けば、立場が伝わります。**なお、**求人票の応募条件で、技術の実務が必須とされている場合**は、範囲が異なります。**「規程・運用」「内部監査」「委託先の管理」**を求める求人を探してください。読み方は[求人票の読み方｜どこを見れば実態が分かるか](senko-sagasu-kyujinhyo.html)に整理しています。

### 事案への対応の経験は、どこまで話せますか

**手順までは話せます。**「守秘の義務があるため、個別の事案には触れられませんが、進め方としては」と前置きしてください。そのうえで、**初動で何を確認したか、誰に報告したか、どの範囲を止めたか、記録に何を残したか**を説明します。**事案を特定せずに、判断の過程は伝えられます。**書かない・話さないのは、**発生の時期、関係者、影響の範囲が分かる記述**です。**判断に迷う内容は、書かないでください。**扱いは[警察官から民間へ](senko-tachiba-keisatsu.html)に整理した考え方と同じです。

### 資格の要件を満たしているか分かりません

**所管するところの公表を確認してください。**受験や登録の要件は、**実務の経験の年数や内容で定められていることがあります。**どの職務が該当するかは、**公表されている案内で確認**するのが確実です。**人づての情報や、以前の記憶で判断しないでください。**要件は改められることがあります。なお、**在職中に要件を満たしているなら、在職中に進めるほうが負担が小さい**ことがあります。**証明の書類が必要になる場合、所属での手続が要る**こともあります。**時期と手続を、早めに確認**してください。
