**「データを見たいが、抽出を依頼して待つしかない」**という経験をお持ちの方がいらっしゃいます。

**自分で取り出せると、仕事の進め方が変わります。**

この記事では、**その意味**と、**学ぶ範囲**を扱います。

**⚠ 庁内のシステムやデータの取扱いには規程があります。****必ず、所属の情報の担当に確認してから進めてください。**

## データは、使われる前提で持たれています

**官民データ活用推進基本法第11条第1項**です。

> **国及び地方公共団体は、自らが保有する官民データについて、個人及び法人の権利利益、国の安全等が害されることのないようにしつつ、国民がインターネットその他の高度情報通信ネットワークを通じて容易に利用できるよう、必要な措置を講ずるものとする。**

**「容易に利用できるよう」**という言葉が置かれています。

**そして、その前に「権利利益等が害されることのないようにしつつ」**という条件があります。

**つまり、データは、保護しながら使えるようにするもの**という位置づけです。

**保管するだけのものではありません。**

**この考え方は、民間でも同じ**です。

**データを持っていても、取り出せなければ判断に使えません。**

## 自分で取り出せると、何が変わるか

| 場面 | 依頼して待つ場合 | 自分で取り出す場合 |
|---|---|---|
| 確認 | **数日かかる** | その場で分かる |
| 試行 | 依頼が重なり、遠慮する | **何度でも試せる** |
| 条件の変更 | 再度の依頼 | すぐに変えられる |
| 検証 | 結果を受け取るだけ | **定義を確かめられる** |
| 速さ | 相手の都合による | 自分の作業として進む |

**2行目が、最も大きい**です。

**「この条件で見たらどうなるか」を何度も試せるかどうか**で、分析の質が変わります。

**依頼が前提だと、最初の1回で正解を出そうとして、試行が減ります。**

## 学ぶ範囲

| 段階 | 内容 |
|---|---|
| ① 取り出す | 条件を指定して抜き出す |
| ② 並べる・絞る | 並び替え、件数の制限 |
| ③ 集計する | 件数、合計、平均、分類ごとの集計 |
| ④ つなぐ | 複数の表を結合する |
| ⑤ 整える | 日付や文字の加工 |
| ⑥ 書く順序を意識する | 処理の重さを考える |

**①〜③で、日常の確認はおおむね足ります。**

**④が、実務で最も使う**部分です。

**台帳と履歴、申請と決定のように、複数の表を突き合わせる**場面が多いためです。

**⑥は、大量のデータを扱うようになってからで構いません。**

## 行政での経験との接続

| 経験 | 接続する部分 |
|---|---|
| ① 台帳の管理 | **表の構造の理解** |
| ② 抽出の依頼 | 条件を言葉で定義する力 |
| ③ 統計の作成 | 集計の設計 |
| ④ 定義の確認 | **何を数えたものか** |
| ⑤ 突き合わせ | 複数の資料の照合 |
| ⑥ 個人情報の扱い | 取り出してよい範囲の判断 |

**②が効きます。**

**抽出を依頼するとき、「どの条件で、どの項目を、どの期間」**を指定してきたはずです。

**これは、取り出しの条件を言葉にする作業**です。

**自分で書く場合も、同じ整理が先にあります。**

**⑥について。**

**取り出せることと、取り出してよいことは別**です。

**扱いは**[生成AIの業務活用｜自治体での利用経験をどう語るか](skill-seiseiai.html)**にも整理しています。**

## 書き方の例

**悪い例**

> データベースの操作ができます。

**良い例**

> ◯◯に関する台帳（約◯件）について、**条件を指定した抽出と、分類ごとの集計を実施。**申請の台帳と決定の記録を**突き合わせ、処理の状況を月次で確認する手順を整備。****取り出す項目は、公表・共有の範囲に応じて限定し、個人が特定されない形に整理。**

**「件数」「操作の内容」「運用」「配慮」**が入っています。

**基本の型は**[公務員の職務経歴書｜民間で読まれる形にする基本](senko-shokumu-kihon.html)**に整理しています。**

:::insight
データの取り出しについて、**面談でお伝えしているのが「条件を言葉にできることが先です」**という点です。**「操作ができる」ことより、「何を取り出すべきかを決められる」ことのほうが難しい**場面があります。たとえば、「申請が滞っている件数」を出すとしましょう。**どの時点を起点とするか、どの状態を滞っているとみなすか、取り下げられたものを含めるか。****この定義を決めないと、数字が出ません。**行政では、**統計や報告のたびに、この定義を確認してきた**はずです。**そして、定義を確かめずに出した数字が、後から食い違う。**この事故は、民間でも起きています。書類には、**「抽出の条件と、集計の定義を整理したうえで実施」**と書いてください。**操作の技術は入社後に伸びますが、定義を確かめる習慣は、すぐには身につきません。**ご利用は無料です（紹介手数料は採用企業の負担です）。
:::

## 学ぶときの注意

| 注意 | 内容 |
|---|---|
| ① 規程の確認 | **所属の情報の担当へ** |
| ② 業務のデータで試さない | 許可がない限り |
| ③ 公開されているデータで練習 | 統計、オープンデータ |
| ④ 個人情報の扱い | 取り出す項目を限定する |
| ⑤ 更新の操作に触れない | **読み取りに限る** |

**⑤が重要**です。

**学習の段階では、読み取りの操作だけを扱ってください。**

**書き換えや削除の操作は、業務のデータでは行わないでください。**

**⚠ 庁内のシステムに対する操作は、権限と規程の範囲で行うものです。****自己判断で試さないでください。**

## どの転職先で効くか

| 領域 | 使いどころ |
|---|---|
| ① 自治体向けのシステム | **業務と表の構造の理解** |
| ② 業務の改善の支援 | 現状の把握 |
| ③ 集計・報告の部門 | 定期の抽出 |
| ④ 事業の企画 | 数字で確かめる |
| ⑤ 導入の支援 | 移行の確認 |

**⑤について。**

**システムを入れ替える場面では、移行前後のデータの件数や内容を突き合わせる**作業が生じます。

**この確認ができる人**は、導入の現場で必要とされます。

**探し方は**[公務員経験が活きる求人の探し方](senko-sagasu-kyujin.html)**に整理しています。**

## 面接で聞かれやすいこと

| 質問の趣旨 | 用意しておくこと |
|---|---|
| 扱ったデータ | **件数、種類** |
| 条件の決め方 | 定義をどう確かめたか |
| 集計の経験 | 何を、どの単位で |
| 取扱いの配慮 | 項目の限定、公表の範囲 |
| できる範囲 | **正確に、限定して** |

**5行目です。**

**できないことを書かないでください。**

**「条件を指定した抽出と、基本的な集計の経験あり」**という形で、範囲を明示してください。

[経験の言い換えから相談する](../apply.html)こともできます。

## 学ぶ前に考えること

| 確認すること | 内容 |
|---|---|
| ① すでにある経験 | **台帳、抽出の依頼、統計** |
| ② 応募したい求人の条件 | 必須か、歓迎か |
| ③ 目的 | 確認のためか、職務とするためか |
| ④ 期限 | 応募の時期までに間に合うか |

**なお、覚えれば転職できる、という関係にはありません。**

**何を取り出し、どう確かめ、どう使ったか**が、評価の対象です。

## よくある失敗

**1. 「操作ができる」とだけ書く**

**何を取り出したか**を書いてください。

**2. 条件の定義に触れない**

**最も難しい部分**です。

**3. できる範囲を広く書く**

**入社後に困ります。**

**4. 規程を確認せずに試す**

**情報の担当に確認**してください。

**5. 業務のデータで練習する**

**公開されているデータ**を使ってください。

**6. 更新の操作に触れる**

**読み取りに限って**ください。

**7. 取扱いの配慮を書かない**

**取り出してよい範囲の判断**も経験です。

**8. 覚えれば進めると考える**

**どう確かめ、どう使ったか**が評価の対象です。

:::insight
ここまで学ぶ話をしておいて逆のことを言いますが、**自分で書けなくても、依頼の精度が上がるだけで価値があります。**面談で拝見していると、**「書けないので、この分野は無理だ」と考える方**がいらっしゃいます。ところが、**実務で困るのは、依頼の内容が曖昧なとき**です。「だいたいの件数を出してほしい」では、受けた側が何度も確認することになります。一方、**「◯月◯日時点で、状態が◯◯の件を、分類ごとに件数で」**と指定できれば、一度で済みます。**この指定ができる人は、技術の担当者から重宝されます。**そして、**この力は、抽出を依頼してきた経験から身につきます。**ですから、書類には、**「抽出の条件を定義して依頼し、結果を検証したうえで報告に使用」**と書いてください。**書ける人と、頼める人の両方が必要**です。自分がどちらを目指すかを、先に決めてください。在職中でも、情報収集だけでも構いません。
:::

## まとめ

- **官民データ活用推進基本法第11条第1項**は、**権利利益等が害されることのないようにしつつ、容易に利用できるよう必要な措置を講ずる**としています。**データは保護しながら使えるようにするもの**です
- **自分で取り出せると、試行の回数が増えます。**依頼が前提だと、試行が減ります
- 学ぶのは、**①取り出す ②並べる・絞る ③集計する ④つなぐ ⑤整える ⑥順序**です。**①〜③で日常の確認は足ります**
- 行政での**抽出の依頼の経験**は、**条件を言葉にする力**として接続します
- **取り出せることと、取り出してよいことは別**です
- 学習は、**規程を確認し、公開されているデータで、読み取りに限って**行ってください
- **依頼の精度が上がるだけでも価値があります**

行政が相手の求人もまとまっています。[行政が相手の求人を見てみる](../?gov=1)。

## よくある質問

### 庁内のデータで練習してよいですか

**所属の情報の担当に確認してください。**庁内のシステムやデータの取扱いには、**権限と規程**があります。**自己判断で操作しないでください。**とくに、**個人情報を含むデータ**については、**利用目的の範囲**が定められています。扱いは[生成AIの業務活用｜自治体での利用経験をどう語るか](skill-seiseiai.html)に整理した考え方と同じです。**練習は、公開されているデータで行う**ほうが安全です。統計の公表データや、公開されているデータの一覧が使えます。**許可を得た範囲で、読み取りに限って**行ってください。

### どの程度できれば、応募条件を満たしますか

**求人票の書き方によります。**「基本的な操作ができる方」であれば、**条件を指定した抽出と、集計の経験**で足りることがあります。一方、「設計・構築の経験」が求められている場合は、**範囲が異なります。**判断の目安は、**応募条件の欄**です。読み方は[求人票の読み方｜どこを見れば実態が分かるか](senko-sagasu-kyujinhyo.html)に整理しています。なお、**できる範囲を正確に書いて**ください。**広く書くと、入社後に困ります。**「基本的な抽出と集計の経験あり。結合は学習中」という書き方で差し支えありません。

### 独学で学べますか

**読み取りの範囲であれば、学びやすい部分です。**公開されている学習の環境や、手元の表計算のデータを使った練習ができます。ただし、**実務では、対象の表の構造を理解していることが前提**になります。**どの表に何が入っているかが分からないと、条件を書けません。**行政での台帳や業務の理解は、**この部分で効きます。**なお、**応募の時期が近い場合は、学習の優先順位を下げて**ください。**職務経歴書の作成と、求人を読む作業**のほうが、時期に直接効きます。扱いは[選考スケジュールの組み方](senko-sagasu-schedule.html)に整理しています。
