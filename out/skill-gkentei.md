**庁内の推進に関わってきた方から、「資格を取るべきか」**というご相談を伺います。

**資格は、単独では材料になりにくい**分野です。

この記事では、**組み合わせ方**を扱います。

**⚠ 試験の内容・区分・実施の方法は、実施する団体の公表を確認してください。****この記事では、個別の内容には触れません。**

## 基本理念が、法律に置かれています

**デジタル社会形成基本法第3条**です。

> **デジタル社会の形成は、全ての国民が、高度情報通信ネットワークを容易にかつ主体的に利用するとともに、情報通信技術を用いた情報の活用を行うことにより、デジタル社会におけるあらゆる活動に参画し、個々の能力を創造的かつ最大限に発揮することが可能となり、もって情報通信技術の恵沢をあまねく享受できる社会が実現されることを旨として、行われなければならない。**

**「全ての国民が」「あまねく享受できる」**という言葉が置かれています。

**技術を導入すること自体が目的ではない**という理念です。

**使える人だけが恩恵を受ける形は、この理念と合いません。**

**行政で推進に関わってきた方は、この視点を前提にしてきたはず**です。

**そして、この視点は、民間でも必要とされます。**

**導入したが使われない、という事態を避けるため**です。

## 資格単独では材料になりにくい理由

| 理由 | 内容 |
|---|---|
| ① 範囲が広い | **何ができるかが伝わりにくい** |
| ② 実務との距離 | 知識と、導入の実務は別 |
| ③ 応募条件の記載 | **必須とされることが多くない** |
| ④ 評価の軸 | 何を変えたかが問われる |

**④が中心**です。

**「知っている」ことより、「導入して、使われる形にした」**ことが見られます。

**このため、資格は、推進の経験と組み合わせて書く**のが基本です。

## 組み合わせる材料

| 材料 | 書き方の例 |
|---|---|
| ① 導入の検討 | **目的、対象、比較した案** |
| ② 調達 | 仕様の作成、選定、契約 |
| ③ 業務の整理 | 工程の分解、要件の整理 |
| ④ 運用の定着 | 手順書、研修、問い合わせの対応 |
| ⑤ 結果 | 件数、時間、利用の状況 |
| ⑥ 規律への配慮 | **情報の取扱い、個人情報** |

**④が、最も評価される**部分です。

**入れて終わりではなく、使われる形にした**という事実です。

**手順書を作った、研修を行った、問い合わせに答えた。**

**これらを書いてください。**

**⑥について。**

**扱いは**[生成AIの業務活用｜自治体での利用経験をどう語るか](skill-seiseiai.html)**に整理しています。**

## 書き方の例

**悪い例**

> 庁内のデジタル化の推進を担当しました。

**良い例**

> ◯◯に関する業務について、**現行の工程を◯段階に分解したうえで、導入の目的と対象を整理。****◯案を比較し、費用と効果、法令上の要件を踏まえて選定。**仕様の作成から事業者の選定、**受入れの確認までを担当。****運用の手順書を作成し、職員◯名への研修を◯回実施。**運用の開始から◯か月で、**対象の処理のうち約◯割が新しい手順に移行。**

**「分解」「比較」「調達」「定着」「結果」**が入っています。

**基本の型は**[公務員の職務経歴書｜民間で読まれる形にする基本](senko-shokumu-kihon.html)**に整理しています。**

:::insight
この分野の資格について、**面談でお伝えしているのが「使われる形にした話を先に書いてください」**という点です。**導入そのものは、費用をかければできます。**ところが、**使われずに終わる事例が、行政でも民間でも起きています。**画面が分かりにくい、手順が現場に合わない、問い合わせ先が決まっていない、紙の運用が並行して残る。**これらは、導入の後に起こります。**そして、**行政では、使えない人が取り残されると、制度の趣旨に反します。****デジタル社会形成基本法第3条の「全ての国民が」「あまねく享受できる」という理念**が、そこにあります。**この感覚を持っている人は、民間でも必要とされます。**導入の支援を行う会社では、**「入れた後に定着させる」ことが業務の中心**です。書類には、**「手順書を作成し、研修を実施し、運用の状況を確認した」**と書いてください。**資格の名称より、この経過のほうが評価されます。**ご利用は無料です（紹介手数料は採用企業の負担です）。
:::

## 取る前に考えること

| 確認すること | 内容 |
|---|---|
| ① 応募したい求人の条件 | **必須か、歓迎か、記載なしか** |
| ② 実務で書ける材料 | 導入、調達、定着 |
| ③ 目的 | 用語を揃えるためか、職務とするためか |
| ④ 期限 | 応募の時期に間に合うか |
| ⑤ 他の優先順位 | 書類、条件の整理 |

**③について。**

**用語を揃える目的であれば、体系的に学ぶ意味はあります。**

**技術の担当者と話す際に、言葉が通じる**ようになります。

**一方、技術そのものを職務とするのであれば、範囲が異なります。**

**なお、取れば転職できる、という関係にはありません。**

**何を導入し、どう定着させたか**が、評価の対象です。

## 書くときの注意

| 注意 | 内容 |
|---|---|
| ① 取得の年を書く | いつ取ったか |
| ② 区分を正確に | **段階がある場合** |
| ③ 実務と併記 | 推進の経験と組み合わせる |
| ④ できる範囲を限定 | 技術の実装まで含めない |
| ⑤ 関係するものを選ぶ | 応募先に関係するか |

**④が重要**です。

**資格を書いたことで、実装まで担えると受け取られる**ことがあります。

**「業務側の担当として、要件の整理と定着を担当」**と、**立場を明記**してください。

## 在職中にできること

| 項目 | 内容 |
|---|---|
| 推進の経験の整理 | **導入、調達、定着、結果** |
| 工程の書き出し | 分解した段階 |
| 数字の確認 | 件数、時間、利用の状況 |
| 求人を読む | 週に30分 |

**3行目です。**

**年度の報告や実績の資料から確認**してください。

**根拠のない数は書かないでください。**

[経験の言い換えから相談する](../apply.html)こともできます。

## 面接で聞かれやすいこと

| 質問の趣旨 | 用意しておくこと |
|---|---|
| 導入の目的 | **何を解決しようとしたか** |
| 比較した案 | なぜその案にしたか |
| 定着の工夫 | 手順書、研修、問い合わせ |
| うまくいかなかった点 | 3件、原因と修正 |
| 立場 | **業務側か、技術側か** |

**4行目です。**

**使われなかった経験がある場合、原因と修正を用意**しておいてください。

**なお、特定の事案が分かる説明は避けてください。**

## よくある失敗

**1. 資格だけを書く**

**推進の経験**と組み合わせてください。

**2. 導入したことだけを書く**

**使われる形にした**ことが見られます。

**3. 定着の工夫を書かない**

**手順書、研修、問い合わせ**を書いてください。

**4. 立場を書かない**

**業務側か技術側か**を明記してください。

**5. 結果の数字を書かない**

**件数、時間、利用の状況**を書いてください。

**6. 規律への配慮に触れない**

**情報の取扱い**は前提です。

**7. できる範囲を広く書く**

**実装まで含めない**でください。

**8. 取れば転職できると考える**

**何を導入し定着させたか**が評価の対象です。

:::insight
ここまで「資格単独では弱い」という話をしておいて逆のことを言いますが、**用語を揃えることには意味があります。**面談で拝見していると、**技術の担当者との会話でつまずいた経験を持つ方**がいらっしゃいます。言葉が通じないと、**要件が伝わらず、できないことを依頼してしまう。**その結果、**手戻りが生じます。**体系的に学ぶと、**何ができて、何が難しいかの見当がつく**ようになります。そして、**業務側の担当として、この見当がつくことは強みです。**技術の実装を自分で行う必要はありません。**「これは難しそうだ」「これなら既存の仕組みで足りる」と判断できれば、進み方が変わります。**ですから、**職務とするためでなく、言葉を揃えるために学ぶ**という位置づけもあります。その場合は、**書類には資格と併せて「業務側の担当として」と立場を明記**してください。在職中でも、情報収集だけでも構いません。
:::

## まとめ

- **デジタル社会形成基本法第3条**は、**全ての国民が情報通信技術の恵沢をあまねく享受できる社会の実現**を旨とすると定めています。**技術の導入自体が目的ではありません**
- **資格は単独では材料になりにくい**分野です。**推進の経験と組み合わせて**書いてください
- 組み合わせる材料は、**導入の検討、調達、業務の整理、運用の定着、結果、規律への配慮**です
- **「使われる形にした」**ことを先に書いてください
- **立場（業務側か技術側か）**を明記してください
- **結果の数字**は、記録から確認してください
- **言葉を揃えるために学ぶ**という位置づけもあります

行政が相手の求人もまとまっています。[行政が相手の求人を見てみる](../?gov=1)。

## よくある質問

### 推進の担当ではありませんでしたが、書けますか

**書けます。**担当した業務の中で、**新しい仕組みを入れた、様式を電子に変えた、問い合わせの対応を整理した**という経験があれば、材料になります。書き方は、**「◯◯の手続について、紙の様式での受付を電子での受付に変更。工程を整理し、手順書を作成のうえ、係◯名で運用」**という形です。**規模の大小より、工程を分解して作り直した経験**が評価されます。扱いは[ノーコードツール｜情報政策の経験を実装側へ](skill-nocode.html)にも整理しています。**部署の名称ではなく、やったことで書いてください。**

### 技術の実装はできませんが、応募できますか

**求人によります。**「業務側の担当」「導入の支援」「要件の整理」を求める求人では、**実装の経験が必須でないことがあります。**一方、「設計」「開発」が中心の求人では、**技術の経験が要件**になります。判断の目安は、**求人票の応募条件**です。なお、**自治体向けのシステムの会社では、業務側と技術側で職種が分かれている**ことが一般的です。**業務側の職種を探してください。**扱いは[要件定義｜各課ヒアリングの経験をそのまま職務にする](skill-yoken.html)に整理しています。

### 資格を書くと、実装まで期待されませんか

**立場を明記すれば、誤解は避けられます。**「業務側の担当として、要件の整理と運用の定着を担当」と書いてください。そのうえで、**資格は「知識の裏づけ」として併記**する形です。なお、**面接で、できる範囲を確認される**ことがあります。**正確に、限定して答えて**ください。「要件の整理と、業務側での検証はできます。実装は担当していません」。**できないことを曖昧にすると、入社後に困ります。**扱いは[求人票の読み方｜どこを見れば実態が分かるか](senko-sagasu-kyujinhyo.html)に整理しています。
