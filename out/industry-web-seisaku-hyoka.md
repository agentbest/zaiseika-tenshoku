Web制作会社を調べるとき、公務で必要な情報を確認し、関係課の質問や日程を整理した経験には、工程として示せる接点があります。ただし、サイトを発注・所管したことと、自ら企画、設計、デザイン、実装を担ったことは別です。具体的な求人へ照合します。

本記事は2026年11月時点の公開情報にもとづきます。確認日は2026年11月25日です。制作会社自身の公式募集を使って確認方法を示します。公務員への非公開の評価理由や採用率を示すものではありません。

## 制作の発注者と提供側、職務を分ける

Web制作会社の職務を読む際は、営業、企画や進行を担うディレクション、デザイン、実装、運用等の工程を分けます。一つの会社が複数のサービスを提供していても、本人がすべてを同時に担当するとは限りません。

ウェブラボのディレクター募集は、企画・提案・設計、日程の管理、顧客との連絡・交渉・調整、品質の確認、チームの管理、公開後のフォロー等を挙げています。行政の連絡先へ照会する事務と同じ職務としてまとめないようにします。

サイドスリーのデザイナー募集は、サイトのデザイン、ページやバナー等の作成・更新等を示しています。ディレクターの進行管理と、デザインを自ら作る仕事は別です。管理経験があれば制作技術も経験済みになるとは扱いません。

行政でサイトや広報を担当した場合も、発注、掲載内容の確認、CMSへの入力、企画・設計、デザイン、実装、検証等を分けてください。委託先や他部署が行った技術の作業を、本人の経験へ加えないことが必要です。

会社自身のWebを運営する仕事と、顧客へ制作を提供する仕事も区別します。正式な雇用主、募集職務、仕事の相手を確認し、似た名称の職務の条件を移さないようにします。

[行政に接点のある掲載求人を調べる](../?gov=1)際も、Webへの関心と、本人が担当する工程・契約を別に比較できます。

## 確認と整理の経験を、本人の行動で説明する

公務でページの情報を確認した経験は、対象、根拠、確認した項目、質問、他者の判断に分けて整理できます。誰が読む情報か、何を確かめ、どこに未回答があったかを説明できます。内部資料の複製を用意する必要はありません。

関係課の意見をまとめたことと、サイトの情報構造やデザインを自分で設計したことは別です。本人が日程を整えたのか、要望を整理したのか、制作上の選択を判断したのかを分けてください。組織の成果を一人の権限で実現した実績へ広げません。

ウェブラボの募集にある連絡や品質の確認と、公務の説明・照合の接点は考えられます。ただし、工程の接点があることと、募集の必須経験を満たすことは別です。本人の実務を原文へ対応させ、対象が不明なら窓口へ確認します。

CMSを利用して内容を登録したことと、CMSの選定や構築、テンプレートの開発を行ったことも違います。ツールの名前だけで全機能の実務があるとせず、何を操作したかを具体的に示します。

公務でアクセス等の数値を読んだ場合も、集計したこと、原因を分析したこと、改善案を作ったこと、実装し検証したことを分けます。測っていない成果や増加率を加えず、確認できた工程をそのまま説明できます。

## ディレクターの経験者と未経験者の必須を読み分ける

ウェブラボのディレクター募集は経験者と未経験者を分けています。経験者はプランニングやプロジェクトマネジメントの経験を必須とし、未経験者はExcelやWordの基本操作を必須としています。両区分を混ぜないようにします。

Web制作のプロジェクト進行、Adobe XDやPowerPoint、企画・プレゼン、簡単なHTML等は歓迎として挙げられています。歓迎をすべて必須へ変えず、一方で各区分の必須を省いて何の条件もないともしません。

公務の企画や進行が経験者区分の対象になるかは、具体的な内容で確認します。行政の企画書を扱ったことだけで経験者と決めず、本人が立案・管理した範囲と他者の判断を示してください。未経験の区分も本人の基本操作へ照合できます。

採用FAQにはコミュニケーション、構成、文章、管理、情報収集等の能力の説明がありますが、本人への非公開の採点表ではありません。相手の心理を推測して書類を作るのではなく、何を聞き何を確認したかを示す材料にできます。

熱意や学習意欲等も総合的に見る説明ですが、意欲によって必ず採用される意味にはしません。本人がまだ行っていない設計や制作を、学びたい希望と区別して残します。職務への関心と必須への適合は別です。

:::insight
Webを担当した経験は、発注、内容確認、入力、設計、デザイン、実装を分けることを勧めます。行政側で質問や日程を整理した経験は、その工程として示せます。一方で、委託先が行った制作を自分の実務へ加える必要はありません。ディレクターの募集に接点があっても、経験者か未経験者か、どの条件の対象かを別に確認できます。本人の行動、他者の権限、未経験を原文へ対応させ、不明な対象は質問として残せます。使ったツールの名称だけで実装や設計まで経験済みにせず、何を操作・判断したかを具体的にする方法を使えます。確認済みと未回答の事項も分けて記録できます。
:::

## デザイナーの必須実務を、広報の担当歴で置き換えない

サイドスリーの中途Webデザイナーは、Web制作会社でのデザイン実務2年以上と、Illustrator・PhotoshopでのWebデザイン実務2年以上を応募資格としています。二つの項目をそれぞれ照合し、一方だけでほかが不要と読みません。

アクセシビリティ、アクセス解析やSEO等の知識・経験は歓迎です。これらを学んだことから、必須のデザイン実務がある扱いにはしません。資格や学習と、会社で制作を実施した経験を分けてください。

公務で広報の掲載物を確認した経験や、バナー等の作成を依頼した経験も、制作会社でのデザイン実務とは別です。自ら作った場合は道具、対象、期間、担当範囲を具体的にし、所属先の条件も確認します。行政の在籍を制作会社の勤務へ変えません。

本人に制作の前職や副業等があるなら、公務の履歴と別に勤務先や契約、期間、工程を整理できます。ただし、職務上の規程や権利関係等の確認と、求人要件への照合は別です。未知の実務を補うために経歴を作らないようにします。

## 独立した架空の記入例で、経験と条件を残す

以下は経験整理のための独立した架空例です。実在の応募者、面接の回答、採用実績ではありません。本人が使う場合は事実に置き換え、未実施の行動や持っていない経験は削除してください。

| 項目 | 架空の記入内容 |
|---|---|
| 本人の担当 | 自治体サイトの掲載情報確認と関係課への照会 |
| 実施した作業 | 対象年度と根拠を確認し、未回答の質問を一覧化 |
| 他者の権限 | 掲載方針の決裁は上司、設計・デザイン・実装は制作会社 |
| 道具の経験 | 本人が行った表への入力・集計と説明資料作成 |
| 未経験 | 提供側のWeb設計、デザイン制作、コード実装、受注 |
| 読んだ募集 | ディレクターの区分とデザイナーの必須を分けて確認 |
| 条件の状態 | 制作会社のデザイン実務があるとは記入しない |
| 未確認 | 公務の工程が対象か、初期担当、契約と勤務 |
| 次の行動 | 正式職名と工程を添えて対象を質問する |
| 現職の比較 | 現在の根拠確認や説明を深める進路も残す |

この例では、自治体サイトに関わったことを、サイト制作全体を自ら行った経験へ変えていません。本人の入力や資料整理を消さず、技術的な実務は未経験として残しています。会社側が評価したという架空の反応も加えません。

本人が制作物を用意する場合も、公開可否と著作権、契約、個人情報等を確認します。職務で扱った内部の画面やデータ、委託先の制作物を、名前だけ消して自由に自分の作品として使えるとは判断しないようにします。

[担当工程と応募条件を整理する](../apply.html)場合も、内部資料を渡さず本人の言葉で説明できます。ご利用は無料です（紹介手数料は採用企業の負担）。経験や希望によっては、面談・求人紹介を提供できない場合があります。

## 初期担当、契約、勤務の条件を個別に確認する

サイドスリーの確認したデザイナー募集は中途正社員、試用3か月・条件変更なしです。神戸の勤務地、通常の時間と時差出勤等の説明があります。手当や在宅に関する表記があっても、本人が毎日自由な場所で働ける保証へ広げません。

ウェブラボの確認した募集は試用6か月、短縮の場合あり、月給は募集欄と同じという説明です。一方、雇用区分等の未記載事項は、別会社の条件から補完しません。本人への正式な提示で確認してください。

同社募集の勤務制度の表記やFAQの説明も、本人への適用と実際の働き方を確認する材料です。制度名だけで自由な勤務や残業なしと決めず、初期担当、連携、時間の扱い等を質問します。本記事では制度の法的な適用を断定しません。

研修やOJT等があっても、本人の習熟や希望配属は別です。初期に何を担当し、どこを上長や専門担当へ確認するかを質問できます。業務一覧すべてを最初から一人で担うとも、希望の事務だけに固定されるとも決めません。

本人の希望は必須と調整できる内容へ分けます。場所、通勤、時間、担当等を確認し、未回答を了承済みとして住居や退職の確定予定へ入れないようにします。一般の制度説明と本人の予定役割への回答も別です。

質問への回答を受けても、一般的な可能性の説明と本人の予定役割を分けます。公開条件と違うように見える場合は、正式職名と確認日を添えて照会できます。回答前に都合のよい条件を補完しないようにしてください。

## 提出前の事実を確認し、情報を守る

書類を作成したら、本人が主語の文を実施した事実へ戻して読みます。「制作を管理した」が、日程の連絡か、品質判断か、設計上の意思決定かを分けてください。整理を支援してもらった場合も、本人が最後に内容を確認します。

住民や相談者、事業者の個人情報、非公開の契約、調達、仕様、IDや認証、内部システムや保安等の情報を持ち出しません。名称を消せば使えるとも判断せず、内部資料を私用AIへ入力しないようにします。公開情報と一般化した本人の工程で説明できます。

行政上の便宜や内部人脈を、制作の受注や案件獲得の強みとして提供する約束もしません。本人の確認や説明の経験を話すことと、現職の立場、権限、連絡先を私的に使うことを分けます。

募集が更新された場合は会社・職名と確認日を残して読み直します。書類の作成、送信、案内受領、正式提示を別に記録し、質問したことを回答済みと扱いません。未公開の設問や採点、面接心理も作らないようにします。

現職で情報の根拠確認や説明を深める判断も比較できます。制作会社へ移りたい場合も、提供側のどの工程を担いたいかを確かめます。Webへの関心や応募の開始だけで退職を先に決める必要はありません。

[掲載中の求人を比べる](../)際も、現職を含め、役割と本人の必須条件を同じ表へ並べられます。

:::insight
Webに関わるという共通点があっても、行政の内容確認と提供側の制作では本人の立場と責任が変わります。設計や制作へ移りたいのか、現職の確認や説明を深めたいのかを分ける方法を勧めます。現職で希望する工程を続けられるなら、残る判断も比較対象です。公務経験を低く見る必要はなく、行っていないデザインや実装を加える必要もありません。必須経験、初期担当、権限の分担、契約と勤務を確認し、応募や登録だけで退職を先に決めず、本人への正式な説明と条件がそろった段階で考えられます。公開情報と希望、確定した提示を分け、不明点を保留にすることも判断のための方法です。
:::

## まとめとよくある質問

Web制作会社では職務と採用区分を分けて要件を読みます。行政の所管、本人の確認、提供側の設計・デザイン・実装を区別して照合してください。

### サイトの発注経験は制作経験になりますか

同じとは扱いません。本人が行った連絡や内容確認等を示し、委託先が行った設計・デザイン・実装を本人の実務へ入れません。

### 未経験ディレクターなら条件はありませんか

紹介したウェブラボの区分にもExcel・Word基本操作の必須があります。経験者区分やデザイナーとも条件を分けて確認してください。

### 広報の担当歴でデザインの必須を満たしますか

自動的には扱いません。サイドスリーの募集は制作会社のデザイン等の実務年数を求めています。本人の所属先と工程を原文へ照合します。
