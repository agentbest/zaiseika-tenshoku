**「業務フローを書いたことがない」**とおっしゃる方がいらっしゃいます。

**図にしていないだけで、工程は把握しているはず**です。

この記事では、**その前提**と、**図にする手順**を扱います。

## 工程の把握は、制度として求められています

**行政手続法第6条**です。

> **行政庁は、申請がその事務所に到達してから当該申請に対する処分をするまでに通常要すべき標準的な期間**（略）**を定めるよう努めるとともに、これを定めたときは**（略）**公にしておかなければならない。**

**申請の到達から処分までに「通常要すべき標準的な期間」を定める。**

**この期間は、工程を把握していなければ定められません。**

**受付、要件の確認、内容の審査、決裁、通知の発送。**

**どの工程に、どれだけの日数がかかるか。**

**これを積み上げて、期間が決まります。**

**つまり、業務フローの把握は、制度が前提としている作業**だということです。

**図にしていなくても、頭の中では組み立てている**はずです。

## 業務フローとは何を表すか

| 要素 | 内容 |
|---|---|
| ① 誰が | **担当、係、課、外部** |
| ② 何を | 作業の内容 |
| ③ どの順で | 前後の関係 |
| ④ 何を使って | 様式、システム、台帳 |
| ⑤ どこで分かれるか | **条件による分岐** |
| ⑥ どれだけかかるか | 所要の日数 |

**⑤が要**です。

**「要件を満たす場合」「書類に不備がある場合」「他の課の確認が必要な場合」。**

**分岐を書き出せるかどうかで、図の実用性が決まります。**

**そして、行政の事務は、分岐が多い**という特徴があります。

**制度の要件が細かく定められているためです。**

## 書く手順

| 順 | やること |
|---|---|
| 1 | **起点と終点を決める**（どこから、どこまで） |
| 2 | 担当ごとに列を分ける |
| 3 | 作業を時系列に並べる |
| 4 | 分岐を書き出す |
| 5 | 使う様式・台帳を対応させる |
| 6 | 所要の日数を入れる |
| 7 | 関係者に確認する |

**1を先に決めてください。**

**範囲が決まっていないと、際限なく広がります。**

**7について。**

**自分の理解だけで書くと、実際と違うことがあります。**

**担当に確認して直す**という工程を入れてください。

**この確認の作業自体が、実務では重要**です。

## 行政で身についていること

| 経験 | 業務フローでの使いどころ |
|---|---|
| ① 事務処理の手順の把握 | **工程の分解** |
| ② 要件の分岐 | 条件による分かれ方 |
| ③ 様式・台帳の理解 | 使うものの対応 |
| ④ 決裁の流れ | 承認の工程 |
| ⑤ 標準処理期間 | 所要の日数 |
| ⑥ 引継ぎの資料の作成 | 説明できる形にする |

**⑥について。**

**異動のたびに引継ぎの資料を作ってきた**という経験は、**業務フローの作成と同じ動作**です。

**誰が読んでも同じ処理ができる形にする。**

**これが、図にする目的**です。

## 書き方の例

**悪い例**

> 業務の手順書を作成しました。

**良い例**

> ◯◯に関する事務について、**受付から決定の通知までの工程を◯段階に分解し、担当ごとに整理。****要件による分岐◯件と、不備がある場合の手順を明示。**使用する**様式◯種類と台帳を工程に対応させ、**所要の日数を工程ごとに記載。**係◯名に説明し、内容を修正のうえ、引継ぎの資料として運用。**

**「工程の数」「分岐」「対応」「確認」**が入っています。

**基本の型は**[公務員の職務経歴書｜民間で読まれる形にする基本](senko-shokumu-kihon.html)**に整理しています。**

:::insight
業務フローについて、**面談でお伝えしているのが「分岐の多さを書いてください」**という点です。業務の図を作る作業で、**難易度を決めるのは工程の数ではなく、分岐の数**です。一本道の処理なら、誰でも書けます。**条件によって扱いが変わる処理**を、漏れなく書き出すのが難しい。そして、**行政の事務は、この分岐が多い**という特徴があります。所得の区分で扱いが変わる、世帯の構成で要件が変わる、前年度の状況で判定が変わる。**この複雑さを扱ってきた経験は、民間でも通じます。**とくに、**制度に関わるシステムや、規制を受ける業種の業務**では、同じ複雑さがあります。書類には、**「要件による分岐◯件を整理」**と書いてください。**「手順書を作成」だけでは、この難易度が伝わりません。**ご利用は無料です（紹介手数料は採用企業の負担です）。
:::

## どの転職先で効くか

| 領域 | 使いどころ |
|---|---|
| ① 自治体向けのシステム | **制度の分岐が分かる** |
| ② 業務の改善の支援 | 現状の把握 |
| ③ 導入の支援 | 移行の設計 |
| ④ 業務の受託 | 手順の整備、教育 |
| ⑤ 社内の情報システム | 各部署の業務の把握 |

**④について。**

**窓口や事務を受託する会社では、手順書がそのまま品質を左右**します。

**担当が交代しても同じ処理ができる形にする。**

**この作業を経験している人**は、そこで必要とされます。

**探し方は**[公務員経験が活きる求人の探し方](senko-sagasu-kyujin.html)**に整理しています。**

## 面接で聞かれやすいこと

| 質問の趣旨 | 用意しておくこと |
|---|---|
| 作った範囲 | **起点と終点、工程の数** |
| 分岐の扱い | 何件、どう整理したか |
| 確認の仕方 | 誰に、どう確かめたか |
| 使われたか | **運用されたかどうか** |
| 改善につながったか | 変えた点と結果 |

**4行目です。**

**作っただけで使われていない資料**は、評価が定まりません。

**引継ぎに使った、研修に使った、システムの検討に使った**という事実があれば書いてください。

**なお、特定の事案が分かる説明は避けてください。**

[経験の言い換えから相談する](../apply.html)こともできます。

## 学ぶ前に考えること

| 確認すること | 内容 |
|---|---|
| ① すでにある経験 | **手順書、引継ぎの資料** |
| ② 足りない部分 | 図の記法、ツール |
| ③ 応募したい求人の条件 | 記法の指定があるか |
| ④ 期限 | 応募の時期までに間に合うか |

**②について。**

**記法（書き方の作法）は、会社によって違います。**

**入社後に合わせる部分が多い**ため、応募の前に深く学ぶ必要は高くありません。

**優先すべきは、すでに作った資料の整理**です。

**なお、講座を受ければ転職できる、という関係にはありません。**

**どの範囲を、どう分解し、どう使われたか**が、評価の対象です。

## 見つかりやすい問題

**工程を並べると、次の問題が目に見えるようになります。**

| 問題 | 見え方 |
|---|---|
| 確認の重複 | **同じ内容を二度確かめている** |
| 書類の往復 | 同じ相手との間を行き来している |
| 一人しか処理できない工程 | 担当が1名に集中している |
| 待ちの発生 | 次の工程まで日数が空いている |
| 様式の重複 | 同じ内容を複数の様式に書いている |

**1行目と5行目は、統合できることがあります。**

**3行目は、手順書を整えることで解消に向かいます。**

**4行目について。**

**待ちが生じている工程は、標準処理期間の短縮に直結**します。

**どこで止まっているかが分かれば、対処を検討できます。**

## よくある失敗

**1. 「手順書を作成」で止める**

**工程の数と分岐**を書いてください。

**2. 分岐の数に触れない**

**難易度**が伝わりません。

**3. 起点と終点を決めずに書く**

**際限なく広がります。**

**4. 関係者に確認しない**

**実際と違うことがあります。**

**5. 使われたかを書かない**

**運用されたか**が見られます。

**6. 引継ぎの資料を経験に数えない**

**同じ動作**です。

**7. 記法の学習を先にする**

**既にある資料の整理が先**です。

**8. 講座を受ければ進めると考える**

**どう分解し使われたか**が評価の対象です。

:::insight
ここまで図の話をしておいて逆のことを言いますが、**図を書くこと自体が目的ではありません。**面談で拝見していると、**きれいな図を作ることに時間をかけてしまう方**がいらっしゃいます。ところが、**業務フローを書く目的は、問題を見つけること**です。同じ確認を二度している、書類が往復している、一人しか処理できない工程がある、待ちが発生している。**図にすると、これらが目に見える形になります。**そして、**見つけた問題をどうしたか**が、書くべき内容です。「工程を整理した結果、◯◯の確認が重複していたため統合し、処理の日数を◯日短縮」。**この一文があると、図が道具として使われたことが伝わります。**逆に、図の完成度だけを語ると、**作業として終わっている**と読まれます。**何を見つけ、何を変えたか**を書いてください。在職中でも、情報収集だけでも構いません。
:::

## まとめ

- **行政手続法第6条**は、**申請の到達から処分までに通常要すべき標準的な期間を定めるよう努め、定めたときは公にしておく**ことを定めています
- **この期間は、工程を把握していなければ定められません。**業務フローの把握は、制度が前提としている作業です
- 表すのは、**誰が・何を・どの順で・何を使って・どこで分かれるか・どれだけかかるか**です
- **分岐の数が、難易度を決めます。**行政の事務は分岐が多いという特徴があります
- **起点と終点を先に決めて**ください
- **引継ぎの資料の作成は、同じ動作**です。経験に数えてください
- **図は道具です。**何を見つけ、何を変えたかを書いてください

行政が相手の求人もまとまっています。[行政が相手の求人を見てみる](../?gov=1)。

## よくある質問

### 図として残っていない場合、書けますか

**書けます。**「工程を分解して整理した」という事実があれば足ります。書き方は、**「◯◯の事務について、受付から通知までの工程を◯段階に整理し、分岐を含む手順を文書化」**という形です。**図でも文書でも、動作は同じ**です。なお、**手元に控えがある場合、応募先に見せられるかは別の判断**になります。**庁内の文書には、公表されていない情報が含まれる**ことがあります。**持ち出しや提示の可否は、所属の規程を確認**してください。**内容に触れず、作業の説明にとどめる**のが安全です。

### 分岐が多すぎて、整理しきれません

**範囲を切ってください。**起点と終点を狭く取り、**まず一本道の主要な流れを書く。**そのうえで、**分岐を別に一覧にする**という方法があります。すべてを1枚に収める必要はありません。また、**頻度の低い分岐は、注記として別に記載する**という整理もできます。**「主要な流れ」と「例外の扱い」を分ける**と、読みやすくなります。なお、**この整理の考え方そのものが、要件定義でも使えます。**扱いは[要件定義｜各課ヒアリングの経験をそのまま職務にする](skill-yoken.html)に整理しています。

### 民間の業務も同じように書けますか

**構造は同じです。**誰が、何を、どの順で、何を使って、どこで分かれるか。**この5点は、業種を問いません。**違うのは、**分岐の根拠**です。行政では、**法令や条例が分岐の根拠**になります。民間では、**社内の規程や、取引先との取り決め**が根拠になります。**根拠の所在が変わるだけで、書き方は変わりません。**なお、**入社後にまず確認すべきは、その会社で使われている記法**です。**既存の資料を見て合わせる**のが確実です。**書き方の作法は、会社ごとに違います。**
