**システムの調達に関わってきた方から、「技術側に移れるか」**というご相談を伺います。

**調達の経験は、そのまま材料になります。**

この記事では、**接続の仕方**と、**資格の位置づけ**を扱います。

**⚠ 試験の内容・区分・実施の方法は、提供する事業者の公表を確認してください。****この記事では、個別の内容には触れません。**

## 役務の提供は、複数年の契約になることがあります

**地方自治法第234条の3**です。

> **普通地方公共団体は、第二百十四条の規定にかかわらず、翌年度以降にわたり、電気、ガス若しくは水の供給若しくは電気通信役務の提供を受ける契約又は不動産を借りる契約その他政令で定める契約を締結することができる。**この場合においては、**各年度におけるこれらの経費の予算の範囲内においてその給付を受けなければならない。**

**翌年度以降にわたる契約を締結できる場合**が定められています。

**そして、各年度の予算の範囲内で給付を受けるという条件**が付いています。

**利用した分を継続して支払う形の役務**は、この枠組みと関わります。

**つまり、クラウドの調達では、契約の形と予算の年度の関係を整理する必要がある**ということです。

**この整理を経験している方は、民間でも重宝されます。**

## 調達の経験が接続する部分

| 経験 | 技術側での使いどころ |
|---|---|
| ① 要件の整理 | **何を求めるかを言葉にする** |
| ② 費用の見積り | 構成と利用の量の想定 |
| ③ 契約の形 | 期間、更新、解約 |
| ④ 情報の取扱い | 保管の場所、権限、監査 |
| ⑤ 移行の計画 | 現行からの切替え |
| ⑥ 受入れの確認 | 完了の条件 |

**②と④が、クラウドの調達に特有**です。

**②について。**

**使った分に応じて費用が変わる形では、利用の量の想定が必要**です。

**この見積りを経験していることは、そのまま説明できます。**

**④について。**

**保管の場所、アクセスの権限、記録の保存。**

**行政では、規程に沿って確認してきた**はずです。

**扱いは**[Googleスプレッドシート｜庁内のExcel運用との違い](skill-spreadsheet.html)**にも整理しています。**

## 資格の位置づけ

| 状況 | 扱い |
|---|---|
| ① 応募条件に記載がある | **満たす材料になる** |
| ② 技術の実務がない | 到達を示すものが他にない |
| ③ 調達の実務がある | **経験のほうが具体** |
| ④ 用語を揃えたい | 学ぶ意味があります |
| ⑤ 目的が曖昧 | 優先順位を下げてください |

**②と④が、取る理由になります。**

**④について。**

**技術の担当者と話す際に、言葉が通じる**ようになります。

**何ができて、何が難しいかの見当がつくと、要件の整理が速くなります。**

**なお、取れば転職できる、という関係にはありません。**

**何を調達し、どう確認したか**が、評価の対象です。

## 書き方の例

**悪い例**

> システムの調達を担当しました。

**良い例**

> ◯◯システムの更改にあたり、**業務側の担当として要件の整理から受入れの確認までを担当。**現行の業務の工程を整理し、**求める機能と性能を仕様に記載。****契約の形と年度の予算の関係を整理し、長期継続契約による調達の可否を確認。****保管の場所と権限の設定、記録の保存について、所属の規程と照らして条件を設定。**移行にあたり、**データの件数を移行の前後で突き合わせ。**

**「立場」「要件」「契約の整理」「規律」「検証」**が入っています。

**基本の型は**[公務員の職務経歴書｜民間で読まれる形にする基本](senko-shokumu-kihon.html)**に整理しています。**

:::insight
クラウドの調達について、**面談でお伝えしているのが「契約と予算の整理を書いてください」**という点です。技術の話は、**技術の担当者のほうが詳しい**場合があります。一方、**契約の形と予算の年度の関係を整理できる人は、多くありません。**利用した分に応じて費用が変わる役務を、**年度で区切られた予算の枠組みでどう扱うか。**複数年の契約にするのか、年度ごとにするのか。**増減が生じたときに、どう処理するか。****この整理は、行政の調達を経験した人の強み**です。そして、**自治体を顧客とする事業では、この論点が必ず出ます。**相手の予算の仕組みが分からないと、提案の形が決まりません。書類には、**「契約の形と年度の予算の関係を整理し、調達の方法を決定」**と書いてください。**技術の深さで勝負しなくても、書ける材料があります。**ご利用は無料です（紹介手数料は採用企業の負担です）。
:::

## 技術側へ広げるときの順序

| 順 | やること |
|---|---|
| 1 | **立場を決める**（業務側か、技術側か） |
| 2 | 調達の経験を整理する |
| 3 | 用語を揃える |
| 4 | 応募条件を確認する |
| 5 | 必要なら、資格を検討する |

**1が起点**です。

**業務側の担当として要件を整理する職務**と、**技術側で構築や運用を担う職務**では、求められるものが違います。

**求人票の仕事内容の欄で確認**してください。

**読み方は**[求人票の読み方｜どこを見れば実態が分かるか](senko-sagasu-kyujinhyo.html)**に整理しています。**

## 書くときの注意

| 注意 | 内容 |
|---|---|
| ① 取得の年を書く | いつ取ったか |
| ② 区分を正確に | **段階がある場合** |
| ③ 立場を明記 | 業務側か、技術側か |
| ④ できる範囲を限定 | **構築・運用まで含めない** |
| ⑤ 実務と併記 | 調達の経験と組み合わせる |

**④が重要**です。

**資格を書いたことで、構築まで担えると受け取られる**ことがあります。

**「業務側の担当として、要件の整理と受入れの確認を担当」**と、**立場を明記**してください。

## 在職中にできること

| 項目 | 内容 |
|---|---|
| 調達の経験の整理 | **要件、契約、費用、移行** |
| 規程の確認 | 情報の取扱い、権限 |
| 用語の学習 | 長く続ける前提で |
| 求人を読む | 週に30分 |

**1行目を先にしてください。**

**手元にある材料を整理すると、足りないものが分かります。**

**2行目について。**

**情報の取扱いの規程は、応募先でも同じ論点になります。**

**どの条件で確認したかを覚えておいてください。****面接で問われることがあります。**

[経験の言い換えから相談する](../apply.html)こともできます。

## よくある失敗

**1. 技術の深さで勝負しようとする**

**契約と予算の整理**が書ける材料です。

**2. 立場を書かない**

**業務側か技術側か**を明記してください。

**3. 要件の整理を書かない**

**言葉にする作業**が中心です。

**4. 費用の見積りに触れない**

**利用の量の想定**が特有の論点です。

**5. 情報の取扱いを書かない**

**規程との照合**は経験です。

**6. できる範囲を広く書く**

**構築まで含めない**でください。

**7. 資格だけを書く**

**調達の経験**と組み合わせてください。

**8. 取れば転職できると考える**

**何を調達し、どう確認したか**が評価の対象です。

:::insight
ここまで「調達の経験が書ける」という話をしておいて逆のことを言いますが、**技術側に移るなら、手を動かす機会を作ってください。**面談で拝見していると、**調達の経験だけで技術側の求人に応募し、面接で具体を問われて止まる方**がいらっしゃいます。要件を整理できることと、**実際に構成を組めることは別**です。そして、**技術側の求人では、後者が問われます。**対処は2つです。1つは、**業務側の職種を選ぶこと。**要件の整理、導入の支援、調達の支援であれば、**いまの経験がそのまま使えます。**もう1つは、**個人の環境で試すこと。**⚠ ただし、**庁内のデータや権限を使わないでください。**公開されている範囲で、自分の環境で試す形にしてください。**どちらを選ぶかを、先に決めてください。**在職中でも、情報収集だけでも構いません。
:::

## まとめ

- **地方自治法第234条の3**は、**翌年度以降にわたる契約を締結できる場合**を定め、**各年度の予算の範囲内で給付を受ける**としています
- **クラウドの調達では、契約の形と予算の年度の関係を整理する必要**があります
- 接続するのは、**要件の整理、費用の見積り、契約の形、情報の取扱い、移行の計画、受入れの確認**です
- **費用の見積り（利用の量の想定）と、情報の取扱い**が、この分野に特有の論点です
- **資格は、用語を揃える目的か、技術の実務がない場合に材料**になります
- **立場（業務側か技術側か）を明記**してください
- **技術側に移るなら、手を動かす機会を作って**ください

行政が相手の求人もまとまっています。[行政が相手の求人を見てみる](../?gov=1)。

## よくある質問

### 調達の担当でしたが、技術は分かりません

**業務側の職種を探してください。**「要件の整理」「導入の支援」「調達の支援」「業務側の担当」と書かれた求人では、**技術の実装の経験が必須でないことがあります。**とくに、**自治体を顧客とする事業では、発注する側の考え方を知っている人**が求められます。仕様の作り方、予算の時期、受入れの確認の観点。**これらは、調達を経験していないと分かりません。**扱いは[要件定義｜各課ヒアリングの経験をそのまま職務にする](skill-yoken.html)に整理しています。**技術が分からないことを理由に、候補を狭めないでください。**

### 資格を取ると、技術側に移れますか

**資格だけでは、判断されません。**技術側の求人では、**構築や運用の実務の経験**が問われることがあります。資格は、**知識の裏づけとして併記するもの**です。なお、**用語を揃える目的であれば、学ぶ意味があります。**技術の担当者との会話で、**何ができて何が難しいかの見当がつく**ようになります。判断の目安は、**求人票の応募条件**です。「実務経験◯年以上」と書かれている場合、資格では代えられません。**目的を決めてから、検討してください。**

### 庁内の環境で試せません

**個人の環境で、業務の情報を用いずに試してください。**⚠ **庁内のデータや権限を個人の環境で使わないでください。**規程に反するおそれがあります。**判断に迷う場合は、所属の情報の担当に確認**してください。なお、**試した内容は、書類に書けます。**「個人の環境で、◯◯の構成を作成し、動作を確認」という形です。**業務の情報を使っていないことを明記**してください。扱いは[SQL｜データを自分で取り出せることの価値](skill-sql.html)にも整理しています。
