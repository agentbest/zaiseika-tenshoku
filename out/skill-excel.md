**「表計算はどこまでできれば足りるのか」**というご相談を伺います。

**最初に問われるのは、速さではありません。**

この記事では、**水準の目安**と、**行政で身についている習慣**を扱います。

## 数字は、別の人が検査する前提で作られます

**地方自治法第235条の2第1項**です。

> **普通地方公共団体の現金の出納は、毎月例日を定めて監査委員がこれを検査しなければならない。**

**同条第3項**です。

> **監査委員は、第一項の規定による検査の結果に関する報告**（略）**を普通地方公共団体の議会及び長に提出しなければならない。**

**毎月、別の機関が検査し、その結果を報告する。**

**この仕組みが、制度として置かれています。**

**つまり、行政で扱う数字は、「後から別の人が確かめる」ことを前提に作られている**ということです。

**そのため、根拠が追えるように作る、検算する、記録を残すという習慣が身につきます。**

**この習慣こそが、民間で最初に問われる水準**です。

## 最初に問われる水準

| 段階 | 内容 | 目安 |
|---|---|---|
| ① 入力と書式 | 見やすく、統一して入力する | **できて当然** |
| ② 表の作り方 | **1行1件、1列1項目** | ここが分かれ目 |
| ③ 関数 | 集計、検索、条件の判定 | よく使う範囲 |
| ④ 分類ごとの集計 | 集計の機能 | 実務で頻出 |
| ⑤ 検算 | **合計が合うかを別の方法で確かめる** | 信用に直結 |
| ⑥ 自動化 | 定型の処理 | 必要になってから |

**②と⑤が中心**です。

**②について。**

**見た目を整えた表は、集計に使えません。**

**セルを結合する、1つの列に複数の情報を入れる、小計の行を途中に挟む。**

**これらをすると、後から集計できなくなります。**

**⑤について。**

**合計を2つの方法で出して突き合わせる。**

**行政の事務では、当たり前に行ってきた作業**です。

## 行政で身についていること

| 習慣 | 民間での意味 |
|---|---|
| ① 根拠の資料と突き合わせる | **数字の出所が追える** |
| ② 検算する | 誤りを残さない |
| ③ 様式を統一する | 誰が作っても同じ形になる |
| ④ 記録を残す | 後から確認できる |
| ⑤ 期限を守る | 締めに間に合わせる |
| ⑥ 引継ぎを前提に作る | 担当が交代しても回る |

**⑥が、実は評価されます。**

**異動のたびに引き継いできたため、「自分にしか分からない表」を作らない習慣**があります。

**民間では、担当者しか使えない表が残り、その人が辞めると回らなくなる。**

**この場面は、実際に起きています。**

## 足すべき範囲

| 要素 | 内容 |
|---|---|
| ① 検索の関数 | 別の表から値を引く |
| ② 条件の判定 | 条件で処理を分ける |
| ③ 分類ごとの集計 | 集計の機能を使う |
| ④ 表の正規化 | **集計できる形に直す** |
| ⑤ 見せる用と作業用を分ける | 作業の表と、報告の表 |
| ⑥ 共有を前提とした作り | 権限、履歴 |

**⑤について。**

**作業のための表と、報告のための表を分ける**という考え方があります。

**作業の表は1行1件で作り、報告の表はそこから集計して作る。**

**1つの表で両方をしようとすると、どちらも中途半端になります。**

## 書き方の例

**悪い例**

> Excelを使った資料の作成ができます。

**良い例**

> ◯◯に関する年間約◯件のデータについて、**1行1件の形で管理の表を整備。**検索と条件の関数を用いて**別表から値を引く仕組みを作り、入力の手間を削減。****合計を2通りの方法で算出して突き合わせる検算の手順**を組み込み、**月次の報告の資料を自動で生成できる形に整備。**担当の交代時の引継ぎにも使用。

**「件数」「構造」「仕組み」「検算」「引継ぎ」**が入っています。

**基本の型は**[公務員の職務経歴書｜民間で読まれる形にする基本](senko-shokumu-kihon.html)**に整理しています。**

:::insight
表計算について、**面談でお伝えしているのが「検算の手順を書いてください」**という点です。**「表計算が使えます」では、水準が分かりません。**ところが、**「合計を2通りの方法で算出して突き合わせる手順を組み込んだ」**と書かれていると、**実務の水準が伝わります。**そして、**この習慣は、民間で不足していることがあります。**関数の参照が1行ずれている、行を追加したのに合計の範囲が古いまま、単位が混ざっている。**これらは、見た目では気づきません。**行政では、**監査や検査を受けることが制度として決まっているため、確認が習慣になっています。**しかも、**誤りがあれば訂正の手続が要る**ため、事前に防ぐ意識が働きます。書類には、**「検算」「突き合わせ」「根拠の資料との照合」**という言葉を使ってください。**関数の名前を並べるより、この一文のほうが効きます。**ご利用は無料です（紹介手数料は採用企業の負担です）。
:::

## どの転職先で効くか

| 領域 | 使いどころ |
|---|---|
| ① 管理部門 | **集計、報告、検算** |
| ② 事務の受託 | 手順の整備 |
| ③ 行政が相手の事業 | 報告の様式の理解 |
| ④ 経理・財務 | 突き合わせ |
| ⑤ 現場の管理 | 進捗の集計 |

**②について。**

**受託した業務では、担当が交代しても同じ処理ができる形**が求められます。

**引継ぎを前提に表を作ってきた経験**は、そこで直接使えます。

**探し方は**[公務員経験が活きる求人の探し方](senko-sagasu-kyujin.html)**に整理しています。**

## 面接で聞かれやすいこと

| 質問の趣旨 | 用意しておくこと |
|---|---|
| 扱った規模 | **件数、項目の数** |
| 使える関数 | **正確に、範囲を明示して** |
| 検算の方法 | どう確かめたか |
| 引継ぎ | 他の人が使えたか |
| 自動化の経験 | あれば、内容 |

**2行目です。**

**できないことを書かないでください。**

**「集計・検索・条件の関数と、分類ごとの集計の経験あり」**という形で、範囲を明示してください。

## 学ぶ前に考えること

| 確認すること | 内容 |
|---|---|
| ① すでにある経験 | **作った表と、その規模** |
| ② 応募したい求人の条件 | どこまで求められているか |
| ③ 足りない部分 | 検索、条件、集計の機能 |
| ④ 期限 | 応募の時期までに間に合うか |

**なお、資格や講座を取れば転職できる、という関係にはありません。**

**どの規模の表を、どう作り、どう確かめたか**が、評価の対象です。

## 集計できない表の直し方

**行政の様式には、印刷を前提にした表が残っていることがあります。**

| よくある形 | 直し方 |
|---|---|
| セルが結合されている | **結合を解き、値を各行に入れる** |
| 小計の行が途中にある | 別の表に分ける |
| 1つの列に複数の情報 | 列を分ける |
| 見出しが2段になっている | 1段にまとめる |
| 空白の行で区切っている | 区分の列を作る |

**1行目が最も多い**です。

**結合されたセルがあると、並び替えも集計もできません。**

**直す手順は、作業用の表を別に作り、そこへ値を展開する**という形です。

**元の様式は、報告用として残して差し支えありません。**

**この作業自体が、実務でよく求められます。**

## よくある失敗

**1. 「使えます」とだけ書く**

**規模と作り方**を書いてください。

**2. 検算の手順を書かない**

**実務の水準**が伝わります。

**3. 見た目を整えた表を作る**

**1行1件、1列1項目**が原則です。

**4. セルを結合する**

**集計できなくなります。**

**5. 作業用と報告用を分けない**

**どちらも中途半端**になります。

**6. 引継ぎを前提にしない**

**担当が交代すると回りません。**

**7. できる範囲を広く書く**

**入社後に困ります。**

**8. 講座を受ければ進めると考える**

**どう作り、どう確かめたか**が評価の対象です。

:::insight
ここまで水準の話をしておいて逆のことを言いますが、**操作の速さを競う必要はありません。**面談で拝見していると、**「若い人のほうが詳しいので不利だ」と考える方**がいらっしゃいます。ところが、**実務で問題になるのは、速さではなく正確さ**です。速く作った表に誤りがあれば、**後の工程すべてが狂います。**そして、**誤りを見つけるのは、たいてい数日後**です。そのときには、**その表を使った資料が外に出ています。**行政では、**この事故を防ぐために、確認の工程が組み込まれています。**ですから、**「速く作れます」ではなく、「確かめてから出します」**と言えるようにしてください。**そのうえで、必要な機能は入社後に覚えられます。**関数は調べれば分かりますが、**確かめる習慣は、すぐには身につきません。**在職中でも、情報収集だけでも構いません。
:::

## まとめ

- **地方自治法第235条の2**は、**毎月例日を定めた現金出納の検査**と、**その結果の議会及び長への報告**を定めています
- **行政の数字は、後から別の人が確かめる前提**で作られます。**根拠を追える形、検算、記録**の習慣が身につきます
- 最初に問われるのは、**①入力と書式 ②表の作り方 ③関数 ④分類ごとの集計 ⑤検算**です
- **②と⑤が分かれ目**です。**1行1件、1列1項目**で作ってください
- **引継ぎを前提に作る習慣**は、民間で評価されます
- **作業用の表と報告用の表を分けて**ください
- **速さではなく正確さ**です。「確かめてから出します」と言えるようにしてください

行政が相手の求人もまとまっています。[行政が相手の求人を見てみる](../?gov=1)。

## よくある質問

### 関数をあまり使っていません

**表の作り方から見直してください。**関数を覚える前に、**1行1件、1列1項目の形**になっているかを確認します。この形であれば、**分類ごとの集計の機能だけで、多くの集計ができます。**そのうえで、**検索の関数と条件の判定**を覚えると、実務の範囲がほぼ埋まります。なお、**応募条件に「基本的な操作」と書かれている場合、この範囲で足りる**ことがあります。読み方は[求人票の読み方｜どこを見れば実態が分かるか](senko-sagasu-kyujinhyo.html)に整理しています。**関数の数を増やすことを目標にしないでください。**

### 資格を取ったほうがよいですか

**応募条件に記載がある場合に、満たす材料になります。**記載がない場合、**判断の中心にはなりません。**なお、**体系的に学ぶ手段としては有効**です。独学では触れない機能を知る機会になります。ただし、**応募の時期が近い場合は優先順位を下げて**ください。**職務経歴書の作成と、求人を読む作業**のほうが、時期に直接効きます。扱いは[選考スケジュールの組み方](senko-sagasu-schedule.html)に整理しています。**資格より、作った表の実物と運用を説明できるほうが伝わります。**

### 共有の環境での作法は違いますか

**権限と履歴の考え方が加わります。**共有を前提とする環境では、**誰に、どこまで見せるか**の設定が操作の一部になります。また、**変更の履歴が残る**ため、数字が変わったときに追えます。なお、**1行1件、1列1項目という原則は、環境が変わっても同じ**です。**表の作り方が正しければ、どの環境でも使えます。**扱いは[Googleスプレッドシート｜庁内のExcel運用との違い](skill-spreadsheet.html)に整理しています。**⚠ 業務のデータを、許可のない環境に置かないでください。**
