Web制作会社の選考は、営業、ディレクション、デザイン、実装等の職務ごとに確認します。会社の一般案内と個別の必須条件、公開フローと本人への正式な案内を分けてください。公務のサイト担当歴は、実施した工程で具体的に準備できます。

本記事は2026年11月時点の公開情報にもとづきます。確認日は2026年11月25日です。制作会社自身の公式募集から確認方法を示します。非公開の設問や採点、面接心理、採用率を示すものではありません。

## 発注者の経験と、提供側の応募職務を区別する

行政でサイトに関わった場合、発注、内容確認、CMSへの入力、設計、デザイン、実装、検証等を分けます。委託先や別部署が行った作業を本人の実務へ加えず、誰が何を担当したかを確認してください。

ウェブラボのディレクター募集は、企画・提案・設計、日程管理、顧客との連絡・交渉、品質やチームの管理、公開後のフォロー等を示しています。会社でWebを提供する職務と、行政で掲載を確認する立場は同じではありません。

サイドスリーのWebデザイナーは、サイトのデザインやページ、バナー等の作成・更新の仕事です。ディレクターの進行管理と、自らデザインを作る実務を分けます。共通するツールを使ったことだけで同じ経験にはしません。

顧客へ制作を提供する仕事と、自社のサイトを運営する仕事も別です。正式な雇用主、職名、仕事の相手、契約を一組で読みます。Webという業界名だけで、どの会社も共通の選考になるとは決めません。

[行政に接点のある掲載求人を調べる](../?gov=1)際も、制作のどの工程へ応募するかを単位に比較できます。

## デザイナーの公開された手順を、当該募集の例として読む

サイドスリーの中途Webデザイナー募集は、書類選考、業務リーダーとの一次面接、役員との最終面接を示しています。上記が変更になる可能性も記載されているため、本人への正式な案内を確認します。

この手順を同社のすべての職種や他の制作会社へ共通のフローとして移しません。新卒や契約の別区分の案内も混ぜず、正式職名と確認日を記録できます。応募する対象が同じかを確かめてから準備します。

公開記載から、面接で必ず求められる作品の種類、課題、テスト、採点を確定しません。確認できないものは質問に残し、本人の経験と未経験、担当への関心を整理できます。面接相手の肩書から心理や評価理由を推測しないようにします。

書類を作ったこと、送信したこと、面接の案内を受領したこと、条件を提示されたことは別の段階です。日時や形式、提出物等は、本人に届く正式な案内で確認してください。応募だけで面接や採用が決まった扱いにはしません。

選考が進むことと、希望する仕事や条件がそろうことも別です。希望を伝えたことを配属確約や勤務条件の承認とせず、本人への回答と正式提示を区別します。未回答の項目は確認事項に残せます。

## ディレクターの応募案内から、未記載の回数を作らない

ウェブラボのディレクター募集は、応募フォームから履歴書、職務経歴書、ほかに示せる資料があれば送る案内です。当該募集の記載から、面接の具体的な回数や全段階を確定しません。サイドスリーのフローを借りて補完しないようにします。

一般の採用FAQには、新卒、研修、ディレクターに求める能力等の説明もあります。新卒に関する案内を在職者の中途の手順へ移さず、本人が使う区分と対象職名を示して窓口へ確認できます。

通年採用の説明も、いつでも必ず選考や採用を受けられる保証ではありません。現在の募集表示と本人の応募区分を確認します。問い合わせたことと、応募条件を満たすと回答されたことを分けてください。

資料の提出案内があっても、内部の画面や委託先の制作物を自由に送ってよい意味ではありません。公開できる内容、権利、契約、個人情報等を確認し、資料を用意することと提出が認められることを区別します。

:::insight
選考の準備では、公開された手順と未確認の段階を分けることを勧めます。一社のデザイナーのフローを、別会社のディレクターへ移す必要はありません。本人の担当工程を具体的にし、発注や内容確認と、自らの設計・デザイン・実装を区別できます。作品や資料を示す場合も、自分が実施した範囲と権利の確認を残してください。公開情報から未記載の課題や採点を作らず、正式な職名で必要物や方法を質問できます。書類、送信、面接案内の受領を段階別に記録すると、本人に届く案内に沿って準備を追加できます。選考の進行と配属の確定も別です。
:::

## 必須の実務と歓迎、採用区分を分けて照合する

サイドスリーのデザイナーは、制作会社でのデザイン実務2年以上と、Illustrator・PhotoshopでのWebデザイン実務2年以上を応募資格としています。二つをそれぞれ確認し、一方だけでほかが不要とは読みません。

アクセシビリティ、アクセス解析やSEO等の知識・経験は歓迎です。学んでいることから必須の制作実務がある意味にはしません。公務の広報担当歴を、制作会社でのデザイン勤務へ変換することも避けます。

ウェブラボのディレクターは、経験者の必須にプランニングやプロジェクトマネジメントの経験、未経験者の必須にExcel・Wordの基本操作を挙げます。区分を混ぜず、本人の実施した作業を原文へ対応させてください。

Web制作の進行、Adobe XDやPowerPoint、企画・プレゼン、簡単なHTML等は歓迎項目です。歓迎を独自に必須へ変えず、一方で各区分の必須も省きません。公務の工程が経験者区分の対象か不明なら、内容を添えて質問できます。

PCの操作は、入力、集計、資料作成等を本人が行った範囲で示せます。未利用のシステムを操作済みにせず、ツール名だけで設計やコード実装を経験済みにもしません。資格や学習は取得、合格、学習中を分けます。

## 面接の説明は、行動と他者の分担で準備する

公務で関係課の意見や予定をまとめた場合、日程を整えたのか、質問を一覧にしたのか、掲載の方針を決めたのかで意味が変わります。「制作を管理した」の一言にせず、本人が実施した工程を具体的にします。

専門判断や決裁を上司・担当部署が行ったなら分担を残します。委託先のデザイン、実装、品質の技術的な確認を、本人が行った作業へ加えないようにします。組織全体の成果を一人の権限で実現した経験にしません。

CMSへ入力したことと、その仕組みを選定・構築したことも別です。アクセス等の数値を見た場合も、集計、原因分析、提案、実装、効果確認を分けます。測っていない増加率や削減時間を加えず、確認できた範囲で説明できます。

相手に分かりやすく説明した経験も、相手の心理や満足度を本人が確認した事実がなければ作りません。何を聞き、どの根拠を確かめ、説明のどこを整理したか等、自分の行動を根拠にできます。

## 独立した架空の準備例で、未経験を残す

以下は選考準備のための独立した架空例です。実在の応募者、面接の回答、採用結果ではありません。本人が使う場合は事実に置き換え、未実施の行動や持っていない経験は削除してください。

| 項目 | 架空の記入内容 |
|---|---|
| 本人の担当 | 自治体サイトの掲載情報の確認と関係課への質問整理 |
| 実施した工程 | 対象年度と根拠を確認し、未回答事項を一覧化 |
| 他者の権限 | 掲載の決裁は上司、設計・デザイン・実装は制作会社 |
| 道具の経験 | 本人が行った表への入力・集計と説明資料作成 |
| 未経験 | 提供側の設計、デザイン制作、コード実装、受注 |
| 条件の照合 | 制作会社でのデザイン実務があるとは記入しない |
| 選考の段階 | 公式募集を読了。応募・面接は未実施 |
| 未受領 | 本人への日時、資料や課題等の具体的な案内 |
| 次の行動 | 正式職名と工程を示して要件と提出物を質問する |
| 現職の比較 | 現在の根拠確認や説明を深める進路も残す |

この例は、自治体サイトに関わったことを、制作の全工程を担当した経験へ変えていません。本人の確認や整理を示しながら、未経験の設計や制作も残しています。面接を受けた結果や会社の反応を架空に加える必要はありません。

本人に制作の前職等がある場合は、勤務先や契約、期間、対象、工程を公務の履歴と別に示せます。在籍全体と特定の作業の期間を分け、複数業務の分担や他者の権限も残してください。学習や見学は実務と区別します。

[経験と応募先の準備を整理する](../apply.html)場合も、内部資料を渡さず本人の言葉で説明できます。ご利用は無料です（紹介手数料は採用企業の負担）。経験や希望によっては、面談・求人紹介を提供できない場合があります。

## 資料を示す前に、担当範囲と権利を確かめる

公開されたサイトでも、その全部が本人の制作物ではありません。本人が行った内容確認や入力等と、制作会社が作ったデザイン・コードを分けて説明します。担当した工程を省いて、自分がすべて作ったように資料をまとめないでください。

職務で扱った内部の画面、未公開ページ、仕様、IDや認証、アクセス情報等を、名前だけ消して使えるとは判断しません。公開可否、契約、権利、個人情報を確認し、必要なら一般化した工程の説明にとどめます。

応募用に学習等で作ったものを使う場合も、実務の制作実績と区別します。他人の素材やテンプレート等の利用条件を確認し、作業のどこを自分で行ったかを示せる形にします。作品を増やすために架空の発注や成果を加えません。

提出が必要か、形式や容量、提出先は本人への正式な案内で確認します。求められていない資料や第三者の連絡先を追加せず、送信前に本人が対象職名と宛先、添付物を確かめられます。

## 契約と勤務、初期の分担を確認する

サイドスリーの確認した募集は中途正社員で、試用3か月・条件変更なしです。神戸の勤務地や通常の時間、時差出勤等の説明があります。別の職種や会社へ同じ条件を移さず、本人の正式な提示で確認します。

ウェブラボは試用6か月、短縮の場合あり、月給は募集欄と同じとしています。一方、雇用区分等の未記載事項をサイドスリーから補完しません。本人への説明で確認する項目として残します。

勤務制度の表記やFAQは、本人への適用と実際の働き方を確認する材料です。制度名だけで残業なしや自由な勤務と決めず、初期担当、連携、時間の扱い等を質問します。本記事では制度の法的適用を断定しません。

OJT等の説明があっても、本人の習熟や希望担当の保証ではありません。どの工程を、誰へ確認しながら担うかを質問できます。募集の業務一覧すべてを最初から一人で担うとも、関心のある事務だけに固定されるとも考えません。

本人の生活条件は必須と調整できる希望へ分けます。通勤、場所、時間、担当等を確認し、未回答を了承済みとして住居や退職の確定予定へ入れないようにします。一般的な制度説明と本人の予定役割への回答も区別します。

## 提出前の事実確認と、情報の扱いを守る

書類を作成したら、本人が主語の文を実施した事実へ戻して読みます。短くしたことで他者の権限や未経験が消えていないか確かめます。整理を支援してもらった場合も最後は本人が確認し、内容を説明できる形を保ちます。

住民や相談者、事業者の個人情報、非公開の契約、調達、仕様、内部システムや保安等の情報を持ち出しません。名称を消せば使えるとも判断せず、内部資料を私用AIへ入力しないようにします。公開情報と一般化した担当工程で説明できます。

行政上の便宜や内部人脈を、制作の受注や案件獲得の強みとして提供する約束もしません。本人の確認や説明の経験を話すことと、現職の立場、権限、連絡先を私的に使うことを分けます。

募集が更新されれば会社・職名と確認日を残して読み直し、古い資料や他社の条件を混ぜません。書類の作成、送信、案内受領、正式提示を別の段階で記録し、質問したことを回答済みと扱わないようにします。

現職で情報の根拠確認や説明を深める判断も比較できます。制作会社へ移りたい場合も、提供側でどの工程を担いたいかを確かめます。面接の案内や応募の開始だけで退職を先に決める必要はありません。

[掲載中の求人を比べる](../)際も、現職を含め、本人が望む役割と必須の勤務条件を同じ表へ並べられます。

:::insight
選考が進むことと、本人に合う役割や勤務がそろうことは別です。現職で情報の確認や説明を深めたいのか、制作会社で設計やデザイン等を担いたいのかを分ける方法を勧めます。現職で希望する工程を続けられるなら、残る判断も比較対象です。公務経験を低く扱う必要はなく、行っていない実装や制作を加える必要もありません。必須経験、初期担当、分担、契約と勤務を確認し、応募や登録だけで退職を先に決めず、本人への正式な説明と条件がそろった段階で考えられます。公開フローと本人の案内を分け、未回答を保留にすることも判断のための方法です。
:::

## まとめとよくある質問

Web制作会社の選考は会社と職務ごとに確認します。必須実務、作品の権利、本人の担当範囲、公開手順と未確認の案内を分けて準備してください。

### 制作会社の面接回数は共通ですか

共通とは扱いません。紹介したデザイナーの手順は当該募集の例で、変更の可能性もあります。別会社の未記載の回数を補完しません。

### 自治体サイトを自分の制作実績として示せますか

公開可否や権利、担当範囲等の確認が必要です。内容確認と委託先のデザイン・実装を分け、本人が全制作を行ったように説明しません。

### 必ず出る課題や技術の質問は分かりますか

公開情報から未記載の設問や採点は確定できません。本人の工程と未経験を整理し、必要な資料や方法は正式な案内で確認します。
