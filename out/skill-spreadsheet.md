**庁内の表計算と、共有を前提とする表計算では、運用が違います。**

**その違いには、理由があります。**

この記事では、**理由**と、**移ったときに戸惑う点**を扱います。

**⚠ 庁内のデータの取扱いには規程があります。****必ず、所属の情報の担当に確認してください。**

## 安全管理の措置が義務づけられています

**個人情報の保護に関する法律第66条第1項**です。

> **行政機関の長等は、保有個人情報の漏えい、滅失又は毀損の防止その他の保有個人情報の安全管理のために必要かつ適切な措置を講じなければならない。**

**同条第2項**は、**この規定を準用する場合**を挙げています。

> 一 **行政機関等から個人情報の取扱いの委託を受けた者** 当該委託を受けた業務
>
> 二 **指定管理者**（略）

**委託を受けた者や指定管理者にも準用される**という点に注目してください。

**つまり、この規律は、行政の側だけの話ではありません。**

**受託する民間の会社も、同じ扱いを求められます。**

**庁内で、保存の場所や共有の方法に手続がある**のは、この義務があるためです。

**そして、行政を相手とする事業に移った場合も、同じ規律の中で働くことになります。**

## 運用の違い

| 項目 | 庁内で多い運用 | 共有を前提とする運用 |
|---|---|---|
| 保存の場所 | 庁内の共有の領域 | **クラウド上** |
| 共有 | ファイルを送る | **場所を共有する** |
| 同時の編集 | 原則しない | **同時に編集する** |
| 版の管理 | 名前に日付を付ける | **履歴が自動で残る** |
| 権限 | 領域ごと | **ファイル・範囲ごと** |
| 持ち出し | 手続が必要 | 権限の設定による |

**3行目と4行目が、最も戸惑う部分**です。

**同時に編集できるため、「誰かが開いていて編集できない」という場面がなくなります。**

**一方、「いつの間にか数字が変わっている」ことも起こります。**

**履歴で確認する**という習慣が要ります。

## 移ったときに戸惑う点

| 場面 | 起きること |
|---|---|
| ① 版の管理 | **名前に日付を付ける運用が不要になる** |
| ② 共有の範囲 | 権限の設定を誤ると、見えてはいけない人に見える |
| ③ 同時の編集 | 他の人の作業が同じ画面に反映される |
| ④ 関数の違い | 一部の関数の名称や動きが異なる |
| ⑤ 印刷の扱い | 画面で見る前提の設計が多い |

**②が、最も注意を要する点**です。

**共有の設定を広くしたまま、個人情報を含む表を置かない。**

**この判断は、行政で身につけた感覚がそのまま使えます。**

**⚠ 業務のデータを、許可のない環境に置かないでください。**

## 何が評価されるか

**操作の速さではありません。**

| 要素 | 内容 |
|---|---|
| ① 権限の設計 | **誰に、どこまで見せるか** |
| ② 表の作り方 | 後から集計できる形か |
| ③ 入力の統制 | 誤りが入りにくい様式か |
| ④ 引継ぎ | 他の人が使えるか |
| ⑤ 履歴の確認 | 変更を追えるか |

**②が、実務では最も効きます。**

**見た目を整えた表は、集計に使えないことがあります。**

**1行1件、1列1項目で作る**という原則を守れるかどうか。

**行政の台帳や統計の様式は、この形で作られていることが多い**はずです。

## 書き方の例

**悪い例**

> 表計算ソフトを使った資料の作成ができます。

**良い例**

> ◯◯に関する管理の表を作成し、**係◯名で共有して運用。**入力の誤りを防ぐため、**選択式の入力と条件による表示の切り替えを設定。**集計の手順を様式として整備し、**担当が交代しても同じ形で作成できるように運用。**個人が特定される項目は**別に管理し、共有の範囲を限定。**

**「共有」「統制」「引継ぎ」「配慮」**が入っています。

**基本の型は**[公務員の職務経歴書｜民間で読まれる形にする基本](senko-shokumu-kihon.html)**に整理しています。**

:::insight
表計算について、**面談でお伝えしているのが「権限の設計を書いてください」**という点です。**「表計算が使えます」と書かれても、水準が分かりません。**ところが、**「共有の範囲を限定し、個人が特定される項目は別に管理した」**と書かれていると、**扱いの確かさが伝わります。**そして、**この判断は、民間でも必要とされています。**共有の設定を広くしたまま顧客の情報を置く、退職した人の権限が残っている、取引先の情報が社内の全員に見える。**これらは、実際に起きています。**行政では、**個人情報の保護に関する法律第66条の安全管理措置があるため、この感覚が習慣になっています。**しかも、**同条第2項により、委託を受けた者や指定管理者にも準用されます。****行政を相手とする事業では、入社後すぐにこの感覚が要る**ということです。ご利用は無料です（紹介手数料は採用企業の負担です）。
:::

## 学ぶ範囲

| 段階 | 内容 |
|---|---|
| ① 基本の操作 | 入力、書式、印刷 |
| ② 関数 | 集計、検索、条件 |
| ③ 集計の機能 | 分類ごとの集計 |
| ④ 共有の設定 | **権限、範囲** |
| ⑤ 入力の統制 | 選択式、入力の制限 |
| ⑥ 自動化 | 定型の処理 |

**④を飛ばさないでください。**

**共有を前提とする環境では、権限の設定が操作の一部**です。

**⑥は、必要になってからで構いません。**

## どの転職先で効くか

| 領域 | 使いどころ |
|---|---|
| ① 行政が相手の事業 | **同じ規律の中で働く** |
| ② 管理部門 | 集計、共有 |
| ③ 業務の改善の支援 | 様式の設計 |
| ④ 事務の受託 | 手順の整備 |
| ⑤ 現場の管理 | 進捗の共有 |

**①について。**

**受託や指定管理では、行政と同じ安全管理の措置が求められます。**

**扱ってよい範囲の判断ができる人**は、そこで必要とされます。

**探し方は**[公務員経験が活きる求人の探し方](senko-sagasu-kyujin.html)**に整理しています。**

## 面接で聞かれやすいこと

| 質問の趣旨 | 用意しておくこと |
|---|---|
| 作った表の用途 | **誰が、何に使ったか** |
| 共有の範囲 | 権限をどう設定したか |
| 入力の統制 | 誤りを防ぐ工夫 |
| 引継ぎ | 他の人が使えたか |
| できる範囲 | **正確に、限定して** |

**5行目です。**

**できないことを書かないでください。**

**「集計と検索の関数、分類ごとの集計の経験あり」**という形で、範囲を明示してください。

[経験の言い換えから相談する](../apply.html)こともできます。

## 学ぶ前に考えること

| 確認すること | 内容 |
|---|---|
| ① すでにある経験 | **作った表と、その運用** |
| ② 応募したい求人の条件 | 指定があるか |
| ③ 環境の違い | 庁内の環境で試せるか |
| ④ 期限 | 応募の時期までに間に合うか |

**③について。**

**庁内の環境では、外部のサービスを使えないことがあります。**

**⚠ 業務の情報を用いずに、個人の環境で練習**してください。

**なお、覚えれば転職できる、という関係にはありません。**

**何を作り、どう運用したか**が、評価の対象です。

## よくある失敗

**1. 「使えます」とだけ書く**

**用途と運用**を書いてください。

**2. 権限の設計に触れない**

**扱いの確かさ**が伝わります。

**3. 見た目を整えた表を作る**

**1行1件、1列1項目**が原則です。

**4. 引継ぎを書かない**

**他の人が使えるか**が見られます。

**5. 履歴の確認をしない**

**共有の環境では変更を追って**ください。

**6. 業務のデータを許可のない環境に置く**

**してはいけません。**

**7. できる範囲を広く書く**

**入社後に困ります。**

**8. 覚えれば進めると考える**

**何を作り、どう運用したか**が評価の対象です。

:::insight
ここまで違いの話をしておいて逆のことを言いますが、**庁内の運用にも理由があります。**面談で拝見していると、**「役所は遅れている」と語ってしまう方**がいらっしゃいます。ところが、**保存の場所や共有の方法に手続があるのは、安全管理の措置が義務づけられているから**です。扱う情報が、**住民の所得、健康、家族の状況**に及ぶためです。**理由を説明できるかどうかで、印象が変わります。**面接では、**「保有個人情報の安全管理の措置が求められるため、外部のサービスの利用には手続が必要でした。共有を前提とする環境でも、権限の設計は同じ考え方で行えます」**と話してください。**制度を理解したうえで新しい環境に移る**という姿勢が伝わります。**前の職場を否定する語り方は、避けてください。**在職中でも、情報収集だけでも構いません。
:::

## まとめ

- **個人情報の保護に関する法律第66条第1項**は、**保有個人情報の漏えい、滅失又は毀損の防止その他の安全管理のために必要かつ適切な措置**を義務づけています
- **同条第2項**により、**委託を受けた者や指定管理者にも準用**されます。**受託する民間の会社も同じ扱い**を求められます
- 運用の違いは、**保存の場所、共有、同時の編集、版の管理、権限**です
- 戸惑うのは、**版の管理と共有の範囲**です
- 評価されるのは、**権限の設計、表の作り方、入力の統制、引継ぎ、履歴の確認**です
- **1行1件、1列1項目**で作る原則を守ってください
- **前の職場を否定する語り方は避けて**ください。**理由を説明**してください

行政が相手の求人もまとまっています。[行政が相手の求人を見てみる](../?gov=1)。

## よくある質問

### 庁内で使えないため、経験を積めません

**個人の環境で、業務の情報を用いずに練習**してください。公開されている統計のデータや、自分で作った架空のデータを使えば、**操作は学べます。**そのうえで、**書類には、庁内で作った表の運用を書いて**ください。「係◯名で共有して運用」「入力の誤りを防ぐ設定」「担当の交代に備えた様式の整備」。**これらは、環境に関わらず同じ**です。なお、**⚠ 業務のデータを個人の環境に持ち出さないでください。**規程に反するおそれがあります。**判断に迷う場合は、所属の情報の担当に確認**してください。

### 関数はどこまで覚えればよいですか

**求人票の応募条件を見てください。**「基本的な操作」であれば、**集計、検索、条件の関数**で足りることがあります。「分析の経験」が求められている場合は、**分類ごとの集計や、複数の表の突き合わせ**まで必要になることがあります。なお、**関数の数を増やすより、表の作り方を正しくするほうが効きます。**1行1件、1列1項目で作られていれば、**後からどのような集計もできます。**逆に、見た目を整えた表は、**関数を知っていても集計できません。**読み方は[求人票の読み方｜どこを見れば実態が分かるか](senko-sagasu-kyujinhyo.html)に整理しています。

### 共有の環境では、何に気をつけますか

**権限の設定と、履歴の確認です。**権限は、**必要な人に、必要な範囲だけ**が原則です。広く共有したまま個人情報を含む表を置かない。**この判断は、行政で身につけた感覚がそのまま使えます。**履歴については、**誰がいつ何を変えたかを確認できる**ため、数字が変わったときに追えます。**「いつの間にか変わっていた」という場面では、履歴を見てください。**なお、**退職や異動があった人の権限を外す**という運用も必要です。**行政の共有の領域でも、同じ管理をしてきた**はずです。
