**情報政策の担当ではない方から、「取る意味があるか」**というご相談を伺います。

**意味が出る場面と、出にくい場面があります。**

この記事では、**その分かれ目**を扱います。

**⚠ 試験の内容・区分・実施の方法は、所管するところの公表を確認してください。****この記事では、個別の内容には触れません。**

## 施策は、自治体自身の責務です

**デジタル社会形成基本法第14条**です。

> **地方公共団体は、基本理念にのっとり、デジタル社会の形成に関し、国との適切な役割分担を踏まえて、その地方公共団体の区域の特性を生かした自主的な施策を策定し、及び実施する責務を有する。**

**「自主的な施策を策定し、及び実施する責務」**と書かれています。

**委託先や国に任せる形ではなく、団体自身が担う責務**とされています。

**そして、施策は情報政策の担当だけで完結しません。**

**窓口、税、福祉、教育、施設。**

**実際に業務を回している部署が関わらなければ、施策は動きません。**

**つまり、非IT職の職員も、この構造の中にいる**ということです。

## 意味が出る場面

| 場面 | 理由 |
|---|---|
| ① システムの更改に関わる | **要件の整理で言葉が要る** |
| ② 調達に関わる | 仕様の理解 |
| ③ 業務の改善を担う | 工程と仕組みの対応 |
| ④ 技術側の求人を見る | 応募条件に記載がある場合 |
| ⑤ 用語を揃えたい | 担当者との会話 |

**①と⑤が中心**です。

**⑤について。**

**「できません」と言われたとき、なぜできないのかが分かる。**

**代替の案を一緒に考えられる。**

**この差が、要件の整理の速さに出ます。**

## 意味が出にくい場面

| 場面 | 理由 |
|---|---|
| ① 応募条件に記載がない | 判断の中心にならない |
| ② 業務側の経験がある | **経験のほうが具体** |
| ③ 応募の時期が近い | 書類の作成が優先 |
| ④ 目的が曖昧 | 「何か取っておきたい」だけ |
| ⑤ 技術を職務としない | 範囲が広すぎることがある |

**②が、公務員からの転職では多い**です。

**窓口でシステムを使ってきた、帳票を整理した、更改で要件を確認した。**

**これらの経験のほうが、具体に書けます。**

**扱いは**[ノーコードツール｜情報政策の経験を実装側へ](skill-nocode.html)**に整理しています。**

## 非IT職が書ける材料

| 材料 | 書き方の例 |
|---|---|
| ① 現場での利用 | **窓口で年間約◯件の処理に使用** |
| ② 不具合の切り分け | 入力の誤りか、仕組みの問題か |
| ③ 帳票の整理 | ◯種類を◯種類に統合 |
| ④ 要件の確認 | 更改にあたり、業務側として参加 |
| ⑤ 手順書の作成 | 操作の手順を係内に共有 |
| ⑥ 問い合わせの対応 | 職員からの質問に回答 |

**②が見落とされやすい**です。

**「動かない」と言われたときに、原因を切り分けてきた**経験があるはずです。

**これは、支援の職務で直接使えます。**

## 書き方の例

**悪い例**

> システムを使う側でした。

**良い例**

> ◯◯業務において、**基幹のシステムを用いて年間約◯件の処理を担当。**更改にあたり、**業務側の担当として現行の帳票◯種類を棚卸しし、要件の確認に参加。****操作の手順書を作成し、係◯名に共有。**職員からの問い合わせについて、**入力の誤りと仕組みの問題を切り分けたうえで、担当課へ連絡。**

**「規模」「更改への関与」「手順書」「切り分け」**が入っています。

**基本の型は**[公務員の職務経歴書｜民間で読まれる形にする基本](senko-shokumu-kihon.html)**に整理しています。**

:::insight
非IT職の方について、**面談でお伝えしているのが「使う側にいた経験は、売り物になります」**という点です。**「システムを使っていただけ」とおっしゃる方**が多いのですが、**自治体向けのシステムの会社が最も欲しがっているのは、現場で使った人**です。どの画面で手が止まるか、どの項目で住民が迷うか、繁忙期に処理が滞るのはどこか。**これは、作る側からは見えません。**そして、**導入の支援や、業務側の担当の職務では、この理解が業務の前提**になります。資格は、**この経験に用語を足すもの**です。順序としては、**経験の整理が先、用語の学習が後**になります。書類には、**「現場で年間約◯件の処理に使用」「不具合の原因を切り分けたうえで連絡」**と書いてください。**資格の名称より、この経験のほうが評価される場面があります。**ご利用は無料です（紹介手数料は採用企業の負担です）。
:::

## 取る前に考えること

| 確認すること | 内容 |
|---|---|
| ① 応募したい求人の条件 | **記載があるか** |
| ② 実務で書ける材料 | 利用、更改、手順書 |
| ③ 目的 | 用語を揃えるためか、職務とするためか |
| ④ 期限 | 応募の時期に間に合うか |
| ⑤ 他の優先順位 | 書類、条件の整理 |

**②を先に並べてください。**

**書ける材料があるなら、受験より書類の作成が先**です。

**なお、取れば転職できる、という関係にはありません。**

**何に使い、どう関わったか**が、評価の対象です。

## 書くときの注意

| 注意 | 内容 |
|---|---|
| ① 取得の年を書く | いつ取ったか |
| ② 区分を正確に | **段階がある場合** |
| ③ 立場を明記 | **業務側か、技術側か** |
| ④ できる範囲を限定 | 設計・開発まで含めない |
| ⑤ 実務と併記 | 現場での利用と組み合わせる |

**③が重要**です。

**資格を書いたことで、開発まで担えると受け取られる**ことがあります。

**「業務側の担当として」**と、立場を明記してください。

## 在職中にできること

| 項目 | 内容 |
|---|---|
| 利用の整理 | **扱った件数、使った機能** |
| 更改への関与の整理 | 参加した会議、確認した内容 |
| 手順書の確認 | 作成したものの控え |
| 求人を読む | 週に30分 |

**1行目です。**

**年度の報告や統計の資料から件数を確認**してください。

**根拠のない数は書かないでください。**

**3行目について。**

**作った手順書は、内容を持ち出さずとも「作成した事実」は書けます。**

**種類と、共有した人数を控えておいてください。**

[経験の言い換えから相談する](../apply.html)こともできます。

## 面接で聞かれやすいこと

| 質問の趣旨 | 用意しておくこと |
|---|---|
| 使っていたシステム | **業務と規模** |
| 更改への関与 | どこまで関わったか |
| 不具合への対応 | 切り分けの仕方 |
| 手順書の作成 | 誰に、何を |
| 立場 | 業務側か、技術側か |

**3行目です。**

**なお、特定の事案やシステムの詳細が分かる説明は避けてください。**

**守秘の義務は、退職した後も続きます。**

## よくある失敗

**1. 「使う側でした」で止める**

**現場の理解**が売り物になります。

**2. 件数を書かない**

**規模**が伝わりません。

**3. 不具合の切り分けを書かない**

**支援の職務で直接使えます。**

**4. 更改への関与を書かない**

**業務側の担当**として参加した事実です。

**5. 立場を書かない**

**業務側か技術側か**を明記してください。

**6. できる範囲を広く書く**

**設計・開発まで含めない**でください。

**7. 実務の整理より受験を先にする**

**書ける材料**を並べてください。

**8. 取れば転職できると考える**

**何に使い、どう関わったか**が評価の対象です。

:::insight
ここまで「経験が先」という話をしておいて逆のことを言いますが、**学ぶと、書ける材料が増えます。**面談で拝見していると、**現場で不具合の原因を切り分けていたのに、それを言葉にできない方**がいらっしゃいます。「なんとなく分かる」状態では、書類に書けません。**体系的に学ぶと、自分がしてきたことに名前が付きます。**入力の検証、権限の設定、データの整合、処理の順序。**名前が付くと、書けるようになります。**そして、**面接でも説明できるようになります。**ですから、**学習の目的を「資格を取ること」ではなく、「してきたことに名前を付けること」**に置いてください。この目的であれば、**途中まで学ぶだけでも効果があります。**受験するかどうかは、**その後で決めて差し支えありません。**在職中でも、情報収集だけでも構いません。
:::

## まとめ

- **デジタル社会形成基本法第14条**は、**地方公共団体が、区域の特性を生かした自主的な施策を策定し、及び実施する責務を有する**としています
- **施策は情報政策の担当だけで完結しません。**非IT職の職員も構造の中にいます
- 意味が出るのは、**システムの更改、調達、業務の改善、技術側の求人、用語を揃えたい場合**です
- 意味が出にくいのは、**記載がない、業務側の経験がある、時期が近い**場合です
- 書ける材料は、**現場での利用、不具合の切り分け、帳票の整理、要件の確認、手順書、問い合わせの対応**です
- **「使う側にいた経験」は、売り物になります**
- **学習の目的を「してきたことに名前を付けること」**に置いてください

行政が相手の求人もまとまっています。[行政が相手の求人を見てみる](../?gov=1)。

## よくある質問

### 技術の仕事に就くつもりはありません

**それでも、意味が出る場面があります。**業務の改善、導入の支援、調達、業務側の担当。**これらは、技術を職務としない職種**です。そして、**用語が分かると、技術の担当者との会話が速くなります。**「できません」と言われたときに、**なぜできないのかが分かり、代替の案を一緒に考えられる。**この差は、実務で効きます。なお、**応募条件に記載がない求人では、判断の中心にはなりません。**扱いは[求人票の読み方｜どこを見れば実態が分かるか](senko-sagasu-kyujinhyo.html)に整理しています。**目的を決めてから、検討してください。**

### 学習の範囲が広く、続きません

**目的を絞ってください。**「してきたことに名前を付ける」という目的であれば、**自分が関わった範囲から始められます。**データの扱い、入力の検証、権限、処理の順序。**業務で見てきた部分から入る**と、続きやすくなります。なお、**受験を前提としない学習でも、書類に書ける材料は増えます。**「業務の改善のために学習し、◯◯の手順を見直した」という形です。**学習と成果がつながっていると、実務に結び付く人として読まれます。**扱いは[MOS｜取るべき人と、取らなくてよい人](skill-mos.html)にも整理しています。

### 現場の経験は、どう書けば伝わりますか

**規模と、判断した場面で書いてください。**「基幹のシステムを用いて年間約◯件の処理を担当」で規模が、**「入力の誤りと仕組みの問題を切り分けたうえで担当課へ連絡」で判断**が伝わります。また、**繁忙期の状況**を書くと、現場の理解が伝わります。「年度の変わり目に処理が集中するため、◯◯の手順を分けて運用」。**作る側からは見えない部分**です。なお、**システムの名称や詳細が分かる記述は避けてください。**業務と動作で書いてください。守秘の義務は、退職した後も続きます。
